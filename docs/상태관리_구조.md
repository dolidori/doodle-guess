# Doodle Guess 클라이언트 상태관리 구조

## 1. 원칙

1. 서버 상태와 로컬 UI 상태를 같은 객체에 섞지 않는다.
2. 추측, 권한, 라운드 결과, 확정 스트로크는 서버 이벤트를 받은 뒤에만 반영한다.
3. 제시어는 PRIVATE 상태에만 저장하고 열람 권한을 잃는 즉시 메모리에서 제거한다.
4. 서버가 수락한 추측만 공개 피드에 넣는다.
5. WebSocket 이벤트는 방별 `eventSeq`, 그림의 `drawingRevision/drawingSeq`, 추측의 `roundId/guessSeq`로 중복·누락·역순을 검사한다.
6. 정답과 시간 종료 모달은 서버의 안정적인 `eventId` 기반 고유 키로 한 번만 큐에 넣는다.
7. 카운트다운은 서버 `roundEndsAt`를 표시할 뿐 클라이언트에서 라운드를 만료시키지 않는다.

[근거: 게임 설명 4~9행, 결정 D-08~D-13, 공통 지침 §1.2·§3.7~§3.8]

## 3. PUBLIC/PRIVATE/LOCAL 경계

| 영역 | 포함 | 포함 금지 |
|---|---|---|
| PUBLIC | 방번호, 모드, 단계, 참가자·연결 상태, drawer, 제한 시간, `roundEndsAt`, 결과, 호스트 종료 시각 | 제시어 원문·정규화 값, 복구 토큰 |
| PRIVATE | 내 playerId, 내 `allowedActions`, 권한이 있을 때의 제시어 원문 | 다른 사용자의 복구 토큰, 서버 정규화 값 |
| LOCAL | 제시어 가림 여부, 폼 입력, 도구 설정, 모달·토스트, 로컬 스트로크 미리보기 | 다른 사용자에게 전파해야 하는 게임 판정 |

- PRIVATE 제시어가 새 `roundId`로 들어오면 `keywordRevealed=false`로 설정한다.
- PRIVATE 제시어가 `null`이 되면 이전 문자열을 보존하지 않는다.
- drawer가 바뀌어도 PUBLIC 그림은 유지하며 이전 drawer의 `localPreview`만 폐기한다.
- round duration slider 값의 권위는 PUBLIC `durationSeconds`다. 로컬은 pending 상태만 갖는다.

[근거: 게임 설명 7~8행, 결정 D-11·D-12, `PLANNING_PROMPT` 제시어 정보 경계]

## 6. `eventSeq` 중복·누락·역순 처리

서버 envelope의 `eventSeq`는 방 전체 논리 이벤트의 순서다. 한 명령에서 파생된 `GUESS_SHARED`와 `ROUND_SOLVED`, `PLAYER_KICKED`와 `PUBLIC_STATE`는 같은 `eventSeq`를 공유할 수 있으므로 `eventSeq`만으로 두 번째 메시지를 버리지 않는다. PRIVATE_STATE와 ERROR처럼 `eventSeq`가 없는 수신자별 이벤트는 별도 키로 처리한다.

```ts
function getEventKey(event: ServerEnvelope): string {
  const stableId = (() => {
    switch (event.type) {
      case 'GUESS_SHARED':
        return event.payload.guessId;
      case 'ROUND_SOLVED':
      case 'ROUND_EXPIRED':
        return event.payload.eventId;
      case 'STROKE_BATCH':
        return `${event.payload.drawingRevision}:${event.payload.strokeId}:${event.payload.batchSeq}`;
      case 'STROKE_UNDONE':
        return `${event.payload.drawingRevision}:${event.payload.drawingSeq}:${event.payload.strokeId}`;
      case 'DRAWING_CLEARED':
        return `${event.payload.drawingRevision}`;
      case 'DRAWING_SNAPSHOT':
        return `${event.payload.snapshotId}:${event.payload.chunkIndex}`;
      case 'PLAYER_KICKED':
        return event.payload.playerId;
      default:
        return `${event.requestId ?? ''}:${event.roomVersion ?? ''}`;
    }
  })();
  return `${event.eventSeq ?? 'direct'}:${event.type}:${stableId}`;
}

function reduceServerEnvelope(
  state: GameClientState,
  event: ServerEnvelope,
): GameClientState {
  const key = getEventKey(event);
  if (state.eventCursor.processedEventKeys[key]) return state;

  if (
    event.eventSeq !== undefined &&
    event.eventSeq > state.eventCursor.lastAppliedEventSeq + 1
  ) {
    return {
      ...state,
      connection: {
        ...state.connection,
        needsResync: true,
      },
    };
  }

  if (
    event.eventSeq !== undefined &&
    event.eventSeq < state.eventCursor.lastAppliedEventSeq
  ) {
    return state;
  }

  const handler = serverDispatchTable[event.type];
  const next = handler(state, event);
  const lastAppliedEventSeq =
    event.eventSeq === undefined
      ? next.eventCursor.lastAppliedEventSeq
      : Math.max(next.eventCursor.lastAppliedEventSeq, event.eventSeq);

  return {
    ...next,
    eventCursor: {
      ...next.eventCursor,
      lastAppliedEventSeq,
      processedEventKeys: {
        ...next.eventCursor.processedEventKeys,
        [key]: true,
      },
    },
  };
}
```

- `needsResync=true`가 되면 `GameProvider`는 게임 intent를 막고 탭 복구 토큰으로 JOIN 복구를 한 번 실행한다.
- `ROOM_SESSION` 직후의 최초·재접속 `PUBLIC_STATE`는 snapshot baseline이므로 현재 `eventSeq`가 1보다 커도 그대로 `snapshotEventSeq`로 설치한 뒤 실시간 gap 검사를 시작한다.
- 새 `PUBLIC_STATE.eventSeq`를 `snapshotEventSeq`와 `lastAppliedEventSeq` 기준으로 채운 뒤 그 이후 이벤트만 적용한다.
- WebSocket 연결 컨텍스트의 현재 roomCode와 `ROOM_SESSION.roomCode`가 다르면 이벤트를 적용하지 않는다.
- 다른 방 이벤트는 진단용 type과 `eventSeq`만 기록하고 payload는 로깅하지 않는다.
- 그림은 `drawingRevision/drawingSeq`, 공개 추측은 `roundId/guessSeq`로 별도의 연속성을 검사한다.
- `GUESS_SHARED`와 `ROUND_SOLVED`는 같은 `eventSeq`여도 서로 다른 event key로 모두 적용한다.

[근거: 공통 지침 §3.8, `PLANNING_PROMPT` 핵심 불변식 1·5]

## 7. 공개 추측 피드 처리

```ts
function reduceGuessShared(
  state: GameClientState,
  event: ServerEnvelope<'GUESS_SHARED'>,
): GameClientState {
  if (event.payload.roundId !== state.publicRoom?.roundId) return state;
  if (state.guessFeed.items.some(item => item.guessId === event.payload.guessId)) {
    return state;
  }

  const items = [...state.guessFeed.items, event.payload]
    .sort((a, b) => a.guessSeq - b.guessSeq)
    .slice(-100);

  return {
    ...state,
    guessFeed: {
      ...state.guessFeed,
      items,
      unseenCount: state.guessFeed.isNearEnd
        ? 0
        : state.guessFeed.unseenCount + 1,
    },
    forms: isOwnPendingGuess(state, event.payload)
      ? {
          ...state.forms,
          guess: { value: '', pendingRequestId: null, error: null },
        }
      : state.forms,
  };
}
```

- 현재 라운드의 최근 100개만 유지하며 101번째부터 가장 오래된 항목을 제거한다.
- React는 문자열을 text node로 렌더하고 HTML로 삽입하지 않는다.
- 서버 거부 응답은 공개 피드에 추가하지 않는다.

[근거: 결정 D-10, 공통 지침 §3.7]

## 8. 결과 모달 큐

```ts
function enqueueOutcomeModal(
  state: GameClientState,
  kind: 'ROUND_SOLVED' | 'ROUND_EXPIRED',
  eventId: string,
  payload: unknown,
): GameClientState {
  const key =
    kind === 'ROUND_SOLVED'
      ? `round-solved:${eventId}`
      : `round-expired:${eventId}`;

  if (state.ui.shownModalKeys[key]) return state;

  return {
    ...state,
    ui: {
      ...state.ui,
      shownModalKeys: { ...state.ui.shownModalKeys, [key]: true },
      modalQueue: [
        ...state.ui.modalQueue,
        { id: key, kind, dismissible: true, payload },
      ],
    },
  };
}
```

- 라이브 `ROUND_SOLVED`와 `ROUND_EXPIRED`만 결과 모달을 enqueue한다.
- 재접속 스냅샷의 phase가 이미 `SOLVED` 또는 `EXPIRED`면 지속 배너만 복원하고 결과 모달을 다시 만들지 않는다.
- 큐의 첫 모달만 렌더한다. `DISMISS_MODAL`은 첫 항목 제거 후 다음 항목을 노출한다.
- 연결 종료 오버레이는 모달 큐보다 높은 계층이며 큐를 삭제하지 않는다.
- 같은 라운드에 이미 outcome이 있으면 다른 outcome 이벤트를 적용하지 않고 `needsResync=true`로 전환한다.

## 9. 라운드 타이머 상태와 effect

### 설정

- 새 방의 PUBLIC 기본 `durationSeconds`는 60이며 다음 라운드는 마지막 서버 확정값을 유지한다.
- `SET_ROUND_DURATION`은 `PREPARING_KEYWORD`이며 내 `allowedActions`에 포함될 때만 보낸다.
- range 값은 20~180이고 5로 나누어떨어져야 한다.
- 드래그 중 `draftSeconds`는 표시만 갱신한다. pointer up·blur 또는 300ms 키보드 debounce 뒤 마지막 값 한 건을 전송해 Rate Limit을 넘지 않는다.
- 요청 중에는 slider를 잠그고, 서버 수락 PUBLIC 상태가 오면 pending을 해제하며 draft를 서버 값으로 맞춘다. 거부 시에도 draft를 서버 값으로 되돌리고 오류를 표시한다.
- 진행 중 slider는 disabled이며 `라운드 진행 중에는 제한 시간을 바꿀 수 없습니다`를 노출한다.

### 표시

```ts
function getRemainingMs(
  roundEndsAt: number | null,
  serverEpochAtAnchor: number | null,
  localMonotonicAtAnchor: number | null,
  localMonotonicNow: number,
): number {
  if (
    roundEndsAt === null ||
    serverEpochAtAnchor === null ||
    localMonotonicAtAnchor === null
  ) return 0;
  const estimatedServerNow =
    serverEpochAtAnchor + (localMonotonicNow - localMonotonicAtAnchor);
  return Math.max(0, roundEndsAt - estimatedServerNow);
}
```

- `GET /api/time` 왕복 샘플 계산은 `WebSocket_이벤트_명세.md` §8.1을 따른다. 연결·재연결 시 3개 유효 샘플 중 최소 RTT를 채택하고, 활성 라운드에서는 15초마다 및 탭 복귀 시 갱신한다.
- `PUBLIC_STATE.serverNow - receivedAt`은 네트워크 지연을 시계 오차로 포함하므로 확정 offset 계산에 사용하지 않는다. 동기화 전 임시 표시에만 사용한다.
- 시간 표시 effect는 phase가 `DRAWING_AND_GUESSING`일 때 앱 전체에 하나만 동작한다. React Strict Mode 재마운트·재접속·라운드 변경 시 이전 scheduler를 정리한다.
- 매 tick에서 값을 1초씩 빼지 않고 위 함수에 현재 `performance.now()`를 넣어 다시 계산한다. 표시 초는 `Math.ceil(remainingMs/1000)`으로 통일한다.
- 탭이 숨겨져도 별도 누적 timer를 만들지 않는다. 복귀 시 현재 시각으로 즉시 재계산한다.
- 남은 시간이 처음 10초 이하가 되면 `TEN_SECOND_THRESHOLD_REACHED`를 dispatch한다.
- `tenSecondWarningRoundIds[roundId]`가 이미 true면 음성·토스트 경고를 반복하지 않는다.
- 0초가 되어도 클라이언트는 phase를 바꾸지 않고 `ROUND_EXPIRED`를 기다린다.

function formatDurationKo(seconds: number): string {
  const minutes = Math.floor(seconds / 60);
  const rest = seconds % 60;
  if (minutes === 0) return `${rest}초`;
  if (rest === 0) return `${minutes}분`;
  return `${minutes}분 ${rest}초`;
}

## 12. intent 전송 규칙

```ts
function requiredAllowedAction(intent: ClientIntent): AllowedAction | null {
  if (intent.type === 'CREATE_ROOM' || intent.type === 'JOIN_ROOM') return null;
  return intent.type;
}

function dispatchIntent(intent: ClientIntent): void {
  if (state.connection.status !== 'CONNECTED') return;
  if (state.connection.needsResync) return;

  const action = requiredAllowedAction(intent);
  if (action === null) {
    if (state.screen !== 'LOBBY') return;
  } else if (!state.privateRoom?.allowedActions.has(action)) {
    return;
  }

  transport.send(intent);
}
```

- `CREATE_ROOM`과 `JOIN_ROOM`은 PRIVATE `allowedActions`가 아니라 로비·연결 상태와 폼 유효성으로 활성화한다.
- `DRAW_STROKE_BATCH`가 있을 때만 펜·지우개 batch intent를 전송한다.
- `SUBMIT_GUESS`, `SET_KEYWORD_AND_START`, `SET_ROUND_DURATION`은 pending 중 중복 전송하지 않는다.
- `DRAW_STROKE_BATCH`는 로컬 미리보기를 허용하지만 서버 확정 상태를 낙관적으로 쓰지 않는다.
- `TOGGLE_KEYWORD_REVEAL`, 도구·색·굵기 변경, 피드 스크롤은 서버 intent가 아니다.
- 서버 오류가 오면 관련 pending만 해제하고 다른 폼 상태는 보존한다.

## 13. 로비 복귀와 폐기

`RESET_TO_LOBBY`, 강퇴, 호스트 30분 미복귀 종료, 서버 재시작 후 방 없음에서 다음을 수행한다.

- PUBLIC/PRIVATE 상태를 `null`로 만든다.
- 제시어 문자열, 그림, 추측 피드, `allowedActions`, 모달·토스트 큐를 폐기한다.
- `eventCursor`를 초기화한다.
- 탭 복구 정보에서 해당 방 항목을 제거한다.
- 최근 접속 목록은 강퇴 여부와 무관하게 로컬 기록 정책대로 유지한다.
- 새로고침 또는 새 PWA 실행도 로비에서 시작하며 자동 JOIN을 실행하지 않는다.
