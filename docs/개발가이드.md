# Doodle Guess 개발 가이드

## 1. 목적과 기준

이 문서는 계획 산출물을 구현으로 옮기는 순서와 단계별 검증 게이트를 정의한다. 구현자는 아래 문서를 우선순위대로 사용한다.

1. `게임 설명.md`
2. `결정_기록.md`
3. `게임_규칙_문서.md`
4. `게임_상태_설계.json`
5. `WebSocket_이벤트_명세.md`
6. 나머지 화면·캔버스·동시성·기술 문서

`IMPLEMENTATION_PROMPT.md`는 위 계획 산출물을 구현 단계와 테스트 게이트로 옮긴 Doodle Guess 전용 실행 문서다. 범용 `GAME_DEVELOPMENT_GUIDELINES.md`와 충돌하면 이 문서와 위 Doodle Guess 계획 산출물을 우선한다.

근거: 게임 설명 1~14행, 공통 지침 §1.2·§3.7·§6.2~6.3, 결정 D-01~D-24.

## 2. 구현 전 절대 조건

- 호스트 연결이 끊겨도 `hostId`와 호스트 권한을 다른 사용자에게 넘기지 않는다.
- 서버가 방·멤버십·역할·`drawerId`·라운드·정답·그림의 유일한 권위다.
- 제시어 원문은 현재 그리기 권한자와 진행자에게만 PRIVATE 상태로 전송한다.
- 서버가 정상 수락한 추측은 해당 방에만 공개하며 다른 방에는 보내지 않는다.
- 최초 정답자 한 명을 방별 명령 큐에서 원자적으로 확정하고 이후 추측을 거부한다.
- 그림의 권위 원본은 정규화 좌표의 벡터 스트로크다.
- 클라이언트가 보낸 역할·작성자·방 식별 주장을 신뢰하지 않는다.
- 영속 DB를 추가하지 않는다. 서버 재시작 시 방이 사라지는 일회성 세션이다.
- 방장 또는 진행자가 라운드 전 20~180초 범위에서 5초 단위로 제한 시간을 정하고 서버가 만료를 판정한다. 기본값은 60초다.

## 3. 구현 순서와 검증 게이트

### 3.1 프로젝트 스캐폴딩

구현:

- `폴더구조.txt`에 맞춰 server, client, shared 패키지를 만든다.
- Node.js, TypeScript, Express, `ws`, React, Vite, zod를 설정한다.
- 단일 HTTP 포트에서 API·정적 파일·WebSocket을 제공할 수 있게 구성한다.
- 테스트 러너, 린트, 타입 검사, 빌드 명령을 마련한다.

검증 게이트:

- 서버 health endpoint가 성공한다.
- 클라이언트 개발 서버와 프로덕션 빌드가 열린다.
- WebSocket 연결 후 버전이 맞지 않는 봉투는 안정된 오류 코드로 거부된다.
- 빈 프로젝트의 타입 검사·단위 테스트·빌드가 통과한다.

### 3.2 공유 계약과 strict 스키마

구현:

- `게임_상태_설계.json`을 TypeScript 타입과 서버 런타임 타입의 기준으로 옮긴다.
- `WebSocket_이벤트_명세.md`의 이벤트 이름을 공용 상수로 한 번만 정의한다.
- 모든 C→S 페이로드를 zod `.strict()` 스키마로 구현한다.
- 방번호, 닉네임, 제시어, 추측, 색상, 굵기, 좌표, 배열 길이, 메시지 크기 상수를 한 곳에 둔다.
- 정답 정규화 함수는 모든 Unicode 공백 문자 제거만 수행한다.

검증 게이트:

- JSON 스키마 문서가 JSON 파서로 읽힌다.
- 명세의 C→S 이벤트마다 정확히 하나의 strict 스키마가 있다.
- unknown key, 잘못된 타입, 과대 문자열·배열, NaN·Infinity·범위 밖 좌표가 거부된다.
- 공백 정규화 표 기반 단위 테스트가 통과하고 대소문자·문장부호는 임의 변환하지 않는다.

### 3.3 방·세션·연결 컨텍스트

구현:

- 서버 메모리에 `Map<roomCode, Room>`을 둔다.
- `100~999` 방번호를 원자적으로 생성하고 활성 방과 중복되지 않게 한다.
- 방별 직렬 명령 큐를 만들고 생성·입장·퇴장·재접속을 큐에서 처리한다.
- 총 30개 논리 슬롯에 호스트·진행자와 재접속 유예 슬롯을 포함한다.
- 서버가 발급한 불투명 세션 토큰은 탭별 `sessionStorage`에 보관한다.
- 호스트는 토큰 우선, 연결 끊긴 원래 닉네임 폴백으로 같은 슬롯을 복구한다.
- 호스트 disconnect 시 자동 이양 함수를 호출하지 않는다.
- 호스트 부재 타이머 30분이 만료되면 방을 종료한다.

검증 게이트:

- 두 탭이 서로 다른 세션과 플레이어로 같은 방에 입장한다.
- 29개 슬롯이 찬 방에 50개 동시 입장 요청을 보내면 정확히 하나만 성공한다.
- 호스트 disconnect/reconnect 반복 중 일반 참여자의 호스트 권한 획득이 0건이다.
- 다른 닉네임 입장은 새 슬롯이며 기존 연결 끊김 슬롯의 역할을 상속하지 않는다.

### 3.4 서버 상태 머신과 권한 엔진

구현:

- Room, Round, Connection 상태를 분리한다.
- 상태별 허용 이벤트와 `allowedActions`를 수신자별로 계산한다.
- 역할 플래그와 현재 `drawerId`를 분리하고 활성 그리기 권한을 한 명으로 제한한다.
- 일반 모드와 진행자 모드의 생성 흐름을 구현하고 방 수명 중 모드 전환을 허용하지 않는다.
- 호스트 또는 진행자만 대기·다음 라운드 준비 상태에서 제한 시간을 바꿀 수 있고 진행 중에는 바꿀 수 없다.
- 제시어를 본 사용자 ID를 라운드에 기록해 해당 라운드 추측 자격에서 제외한다.
- 권한 위임·회수·강퇴·다음 라운드·전체 지우기·되돌리기를 방 큐에서 직렬화한다.
- 제시어 확정과 동시에 서버 `roundEndsAt`을 기록하고 만료 시 roundId guard를 확인해 `ROUND_EXPIRED`로 원자 전이한다.

검증 게이트:

- 각 상태에서 허용되지 않은 모든 이벤트가 문서에 정의된 오류 코드로 거부된다.
- 조작된 `isHost`, `isModerator`, `drawerId`, `authorId`, `playerId`가 효력을 갖지 않는다.
- 위임·회수 경합 뒤에도 활성 `drawerId`가 최대 한 명이다.
- 강퇴 이후 대상의 큐 대기 명령은 실행 시점 재검증으로 거부된다.
- 만료된 이전 라운드 타이머가 새 라운드를 종료시키지 않고 `ROUND_EXPIRED` 이후 그림·추측이 모두 거부된다.

### 3.5 PUBLIC·PRIVATE 상태 빌더

구현:

- PUBLIC 상태는 방·플레이어·라운드·`hasKeyword`·`drawerId`·잠금·공개 추측 피드만 포함한다.
- PRIVATE 상태는 수신자별로 매번 새로 만들고 개인 `allowedActions`를 포함한다.
- 제시어 원문은 현재 그리기 권한자와 진행자에게만 포함한다.
- 정규화 제시어는 서버 메모리 안에서만 사용한다.
- 세션·복구 토큰은 해당 연결의 세션 수립 응답 외에는 포함하지 않는다.
- 로그·오류·분석 데이터에서 제시어와 토큰을 제거한다.

검증 게이트:

- 일반 참여자의 수신 프레임·DOM·로그에서 제시어 원문과 정규화 값 검색 결과가 0건이다.
- 권한 회수 직후 이전 사용자의 후속 PRIVATE 상태에 제시어가 없다.
- 동일한 플레이어·라운드 ID를 의도적으로 사용한 두 방 사이에서 상태 유출이 0건이다.

### 3.6 정답 판정과 공개 추측 피드

구현:

- 서버가 수락한 추측마다 방 단위 순번을 부여한다.
- 추측 문자열, 제출자 ID·닉네임, 순번을 해당 방에 공유한다.
- 추측을 정규화해 서버의 정규화 제시어와 비교한다.
- 첫 정답에서 라운드 상태, winner, solvedAt, 이벤트 순번을 한 번에 기록한다.
- 정답 추측은 정답 확정 이벤트와 함께 방 전체에 공개한다.
- 해결 이후 도착한 추측은 저장·공유하지 않고 동일한 잠금 오류로 거부한다.
- 제한 시간 만료 이후 도착한 추측도 저장·공유하지 않고 시간 종료 오류로 거부한다.
- 클라이언트는 `roundId`와 이벤트 순번으로 모달을 한 번만 표시한다.

검증 게이트:

- 30명의 동시 정답 경합을 100회 반복해 매회 winner와 정답 이벤트가 정확히 하나다.
- 오답을 포함한 수락 추측은 같은 방의 30명에게 동일 순서로 보이고 다른 방에는 0건이다.
- 해결 이후 추측은 피드·로그·winner를 변경하지 않는다.

### 3.7 벡터 캔버스

구현:

- Pointer Events로 마우스·터치·펜을 통합하고 캔버스에만 `touch-action: none`을 적용한다.
- 좌표를 `0~1`로 정규화하고 로컬 미리보기와 서버 확정 스트로크를 분리한다.
- 고정 팔레트의 다색 펜, 3단계 굵기, 지우개, 마지막 스트로크 되돌리기, 전체 지우기를 구현한다.
- 색상은 임의 문자열이 아니라 서버 허용 팔레트 enum으로 검증한다.
- `strokeId`, batch 순번, drawing 순번, drawing revision, drawer epoch를 검증한다.
- 스냅샷은 청크로 보내고 스냅샷 도중 도착한 delta를 순번 기준으로 합친다.
- 느린 수신자는 delta를 중지하고 최신 벡터 스냅샷으로 수렴시킨다.

검증 게이트:

- 같은 벡터 데이터를 모바일 세로·가로·데스크톱에서 기하학적으로 동일하게 렌더링한다.
- 중복 batch, batch gap, stale drawer epoch, stale round/revision이 그림을 변형하지 않는다.
- 권한 변경 시 미전송 로컬 점은 폐기되고 서버 수락분만 남는다.
- 전체 비트맵 프레임의 반복 전송이 네트워크 검사에서 0건이다.

### 3.8 React 상태와 화면

구현:

- `useReducer`와 이벤트 dispatch table로 서버 상태·연결·캔버스·모달·토스트를 분리한다.
- 버튼·입력 활성화는 서버의 `allowedActions`로 결정한다.
- 로비, 역할별 게임 화면, 진행자 제어, 공개 추측 피드, 해결 모달, 재접속·강퇴 화면을 구현한다.
- 정답 모달은 큐에서 한 번만 보여주고 닫힌 후 해결 상태를 화면에 유지한다.
- 클라이언트 카운트다운은 `/api/time` 왕복 측정의 최소 RTT 샘플과 `performance.now()` anchor로 추정한 서버 현재 시각을 `roundEndsAt`에서 빼서 계산하며 서버의 `ROUND_EXPIRED`가 최종 권위다.
- 메시지 수신 시점부터 새 카운트다운을 시작하거나 tick마다 1초씩 직접 차감하지 않는다. 앱 전체에 표시 scheduler를 하나만 두고 Strict Mode 재마운트·재접속·라운드 변경 때 정리한다.
- 탭 복귀 시 즉시 재동기화하고 이전 `roundId`의 callback·응답·경고를 폐기한다.
- 제시어 가리기는 권한자 탭의 로컬 UI 상태로만 관리한다.
- Enter 입장과 추측 제출, 키보드 포커스, ARIA live 영역을 구현한다.

검증 게이트:

- 권한별 컴포넌트 테스트에서 활성·비활성 컨트롤이 `allowedActions`와 일치한다.
- 재접속 상태 주입 직후 현재 라운드·그림·권한·입력 잠금 화면이 복원된다.
- 과거 이벤트 재수신과 중복 프레임이 모달·토스트를 반복시키지 않는다.
- 재접속 직후 남은 시간이 서버 deadline 기준으로 복원되고 시간 종료 안내가 한 번만 표시된다.
- 서로 다른 로컬 벽시계와 0/200/800ms 네트워크 지연에서도 세 클라이언트 표시가 초 단위 경계 오차 1초 이내다.
- 백그라운드 복귀·Strict Mode 재마운트·재접속 뒤 활성 표시 scheduler는 정확히 하나다.
- 서버 expiry callback을 지연시켜도 deadline 이후 그림·추측 입력은 모두 거부된다.
- 모바일 소프트 키보드가 추측 입력과 제출 버튼을 가리지 않는다.

### 3.9 PWA·자산·반응형

구현:

- 기존 `images/icon/icon-192.png`, `images/icon/icon-512.png`을 공개 자산 경로로 복사한다.
- 512 아이콘의 핵심 도안을 maskable 안전영역 안에 둔 전용 maskable 자산과 Apple touch icon을 만든다.
- manifest는 `Doodle Guess`, standalone, orientation any, 보라색 theme/background를 사용한다.
- 앱 셸만 캐시하고 실시간 방 상태를 오프라인 캐시로 복원하지 않는다.
- 업데이트는 진행 중 방을 자동 새로고침하지 않고 안전한 시점에 적용한다.
- Safe Area, `100dvh`, 내부 패널 스크롤, reduced motion을 반영한다.

검증 게이트:

- manifest와 모든 아이콘이 200 응답이며 설치 가능 판정을 받는다.
- 원형·스쿼클 mask 미리보기에서 로고 핵심이 잘리지 않는다.
- 모바일 세로·낮은 가로·태블릿·데스크톱에서 캔버스와 입력이 겹치지 않는다.
- standalone 모드에서 홈바·노치 영역의 필수 조작이 잘리지 않는다.

### 3.10 배포와 운영 안전성

구현:

- production origin allowlist, 메시지 크기 제한, 이벤트별 token bucket을 적용한다.
- WebSocket heartbeat와 포그라운드 복귀 재연결을 구현한다.
- 구조화 로그에는 room 식별자·이벤트 타입·결과 코드만 기록하고 민감 payload를 넣지 않는다.
- 정상 종료·서버 재시작 시 기존 방 복구를 시도하지 않는다.

검증 게이트:

- 잘못된 origin, malformed JSON, 과대 메시지, Rate Limit 초과가 프로세스를 중단시키지 않는다.
- WebSocket이 OPEN이 아닐 때 클라이언트가 요청을 조용히 버리지 않고 사용자에게 알린다.
- 서버 재시작 뒤 기존 방 참가 시 안정된 `ROOM_NOT_FOUND` 처리와 로비 복귀가 동작한다.

## 4. 테스트 계층

| 계층 | 도구 범주 | 필수 대상 |
|---|---|---|
| 단위 | 서버·클라이언트 테스트 러너 | 정규화, 상태 전이, 권한, allowedActions, 좌표·색상·굵기 검증 |
| 통합 | 실제 WebSocket 서버 | 방 격리, 정원 경합, PRIVATE 경계, 정답 경합, 공개 추측, 강퇴, 재접속 |
| 컴포넌트 | DOM 기반 React 테스트 | 역할별 화면, 잠금, 모달 큐, 키보드, 접근성 이름 |
| E2E | 실제 브라우저 자동화 | 다중 탭·다중 방, 포인터 그리기, 정답, 호스트 복귀, PWA 화면 |
| 부하 | WebSocket 부하 클라이언트 | 20×30 기준 부하와 50×30 스트레스, 느린 수신자 |
| 보안·퍼징 | schema/fuzz 테스트 | 방 spoof, 역할 spoof, 과대·중첩 JSON, NaN·Infinity, 로그 누출 |

## 5. 성능 합격 기준

`멀티룸_동시성_설계.md`의 측정 환경을 사용한다.

- 기준 부하: 20개 방 × 30개 연결, 30분
- 스트레스 부하: 50개 방 × 30개 연결, 30분
- 스트로크 서버 수신→관전자 반영: p95 150ms 이하, p99 300ms 이하
- 추측 수신→정답 확정 반영: p95 200ms 이하, p99 400ms 이하
- 방 큐 대기: p95 50ms 이하
- 정상 클라이언트의 누락·중복·다른 방 유출: 0건
- 이벤트 루프 지연: p95 50ms 미만
- CPU 평균: 70% 미만
- 30분 뒤 안정 구간 RSS 증가율: 10% 미만
- 느린 클라이언트 때문에 정상 클라이언트 p95가 악화되는 비율: 20% 미만

## 6. P1 완료 정의

- 계획 문서의 P1 요구와 게임 설명 14개 문장이 자동 또는 수동 테스트에 연결된다.
- `검증_보고서.md`의 필수 항목이 모두 `충족` 또는 정당한 `이 프로젝트 요구로 대체`다.
- 타입 검사, 단위·통합·컴포넌트·E2E 테스트와 production 빌드가 통과한다.
- 방 격리, 제시어 비공개, 최초 정답 단일 확정, 호스트 비이양은 실패 테스트를 포함한다.
- 모바일 실제 기기에서 터치 그리기, 소프트 키보드, Safe Area를 확인한다.
- 코드와 문서에 릴레이·그룹·AI·계정·랭킹·DB 기능이 없다. 점수는 D-22의 정답자 +1·그림 담당자 라운드당 최대 +1만 존재하고 서버 메모리에서 방 수명 동안 유지한다.

## 7. P2와 제외 범위

P2는 P1 완료 뒤 별도 승인으로만 구현한다.

- 도움말
- 효과음과 전역 음소거
- 관전자용 고급 중계 화면
- 라운드 기록 또는 이전 그림 보기
- 접근성 고도화

다음 항목은 구현하지 않는다.

- AI 플레이어와 자동 그리기
- 계정, 랭킹, 장기 통계
- 팀전과 D-22 외 점수제
- 랜덤 제시어 풀
- 릴레이 그리기, 그룹 배정, 순번·턴 수 맞추기
- 자유 색상 선택기와 고급 드로잉 편집
- 영속 저장소와 서버 재시작 방 복구
