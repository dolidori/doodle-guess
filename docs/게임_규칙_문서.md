# Doodle Guess 게임 규칙 문서

## 1. 문서 지위와 근거

- 본 문서는 구현과 QA가 참조하는 게임 규칙의 단일 출처다.
- 구조화된 상태·제약의 단일 출처는 `게임_상태_설계.json`, 통신 이벤트의 단일 출처는 `WebSocket_이벤트_명세.md`다.
- 근거 우선순위는 `게임 설명.md` > 대표님 확정 결정 > `GAME_DEVELOPMENT_GUIDELINES.md` > `PLANNING_PROMPT.md`다.
- `결정_기록.md` D-01~D-24를 모두 반영했다.
- 공통 지침 §2.6과 §6.3의 FIFO 호스트 자동 이양은 `게임 설명.md` 14행과 D-17에 의해 대체된다. 이 게임에서는 호스트 권한을 자동 이양하지 않는다.

## 3. 역할과 현재 권한

역할 플래그와 현재 그리기 권한은 분리한다. 한 사용자가 `isHost=true`, `isModerator=true`이면서 동시에 현재 `drawerId`일 수 있다.

| 행위 | 호스트 | 진행자 | 현재 그리기 권한자 | 일반 참여자 |
|---|---:|---:|---:|---:|
| 공개 상태 보기 | 가능 | 가능 | 가능 | 가능 |
| PRIVATE 제시어 보기 | 현재 그리기 권한자일 때 | 가능 | 가능 | 불가 |
| 제시어 확정 및 라운드 시작 | 현재 그리기 권한자일 때 | 현재 그리기 권한자일 때 | 가능 | 불가 |
| 그림 입력·지우기·되돌리기 | 현재 그리기 권한자일 때 | 현재 그리기 권한자일 때 | 가능 | 불가 |
| 추측 제출 | 제시어를 보지 않았고 진행자가 아닐 때 | 불가 | 불가 | 제시어를 본 적이 없을 때 가능 |
| 그리기 권한 지정·회수 | 대기실에서 가능 | 대기실·활성 라운드에서 가능 | 불가 | 불가 |
| 참여자 강퇴 | 가능 | 가능 | 해당 역할이 함께 있을 때만 가능 | 불가 |
| 라운드 제한 시간 설정 | 일반 모드에서 가능 | 진행자 모드에서 가능 | 해당 역할이 함께 있을 때만 가능 | 불가 |
| 정답 판정 모드 설정 | 대기실에서 가능 | 대기실에서 가능 | 해당 역할이 함께 있을 때만 가능 | 불가 |
| 대기실로 복귀 | 가능 | 가능 | 해당 역할이 함께 있을 때만 가능 | 불가 |
| 다음 라운드 준비 | 일반 모드에서 가능 | 진행자 모드에서 가능 | 해당 역할이 함께 있을 때만 가능 | 불가 |

### 3.1 모드별 초기 역할

- `NORMAL`: 방 생성자는 호스트이자 최초 그리기 권한자다.
- `MODERATOR`: 방 생성자는 호스트이자 진행자이며 최초 그리기 권한자다.
- 대기실에서는 일반 모드 호스트와 진행자가 다른 연결 참여자에게 그리기 권한을 지정하거나 자신에게 회수할 수 있다.
- 방 하나의 `hostId`는 방이 닫힐 때까지 바뀌지 않는다.
- 활성 라운드의 `drawerId`는 정확히 한 명이며, 진행자의 명시적 지정·회수로만 바뀐다.

근거: 게임 설명 5·8·13·14행, D-04, 공통 지침 §2.4.

## 4. 방 수명과 입장

### 4.1 생성과 입장

1. 서버는 `100~999` 범위에서 사용 중이지 않은 방번호를 원자적으로 예약한다.
2. 입장 요청의 방번호는 문자열 정규식 `^[1-9][0-9]{2}$`를 만족해야 한다.
3. 닉네임은 같은 방의 연결 슬롯, 연결 단절 슬롯, 강퇴 목록과 대조한다.
4. 복구로 판정되지 않은 신규 입장은 슬롯 수가 30 미만일 때만 방별 명령 큐에서 승인한다.
5. 마지막 한 자리에 여러 요청이 도착하면 큐에서 먼저 승인된 한 요청만 입장한다.
6. 숫자 전용 입력과 Enter 입장은 클라이언트 편의 기능이며 서버 검증을 대신하지 않는다.

근거: 게임 설명 2·3·10~12행, D-02·D-03, 공통 지침 §1.2·§3.7.

### 4.2 연결 단절 슬롯

- 네트워크 단절은 슬롯을 삭제하지 않고 `connected=false`로만 바꾼다.
- 연결 단절 슬롯도 30명 정원에 포함되며 방이 닫힐 때까지 유지한다.
- 탭이 유지된 재접속은 `sessionStorage`의 복구 토큰을 우선 사용한다.
- 토큰이 없으면 연결 단절 상태인 기존 슬롯과 정확히 같은 닉네임으로 복구할 수 있다.
- 이미 연결된 동일 닉네임의 슬롯을 다른 연결이 탈취할 수 없다.
- 다른 닉네임으로 들어오면 기존 슬롯을 변경하지 않고 새 플레이어 슬롯을 만든다.

근거: 게임 설명 13·14행, D-03·D-15·D-16, 공통 지침 §2.3.

### 4.3 방 종료

- 호스트가 명시적으로 방을 나가면 방을 즉시 `CLOSED`로 전이하고 모든 연결에 종료 사유를 보낸다.
- 호스트 연결이 끊기면 `hostDisconnectedAt`을 기록하고 `expiresAt`을 정확히 30분 뒤로 설정한다.
- 30분 안에 호스트가 복구되면 두 시각을 비우고 방 종료 작업을 취소한다.
- 호스트가 복구되지 않은 채 `expiresAt`에 도달하면 연결된 참여자 유무와 관계없이 방을 닫는다.
- 서버 재시작 시 모든 인메모리 방은 소멸한다.

근거: 게임 설명 14행, D-17·D-18. 공통 지침 §2.6의 즉시 삭제 및 호스트 이양 규칙은 이 규칙으로 대체한다.

## 5. 라운드 상태와 제한 시간

방과 라운드는 다음 대응을 유지한다.

| 방 상태 | 라운드 상태 | 의미 |
|---|---|---|
| `WAITING` | `PREPARING_KEYWORD` | 제시어와 제한 시간을 준비하는 상태 |
| `ROUND_ACTIVE` | `DRAWING_AND_GUESSING` | 그림과 추측을 동시에 받는 상태 |
| `ROUND_SOLVED` | `SOLVED` | 최초 정답자가 확정된 상태 |
| `ROUND_EXPIRED` | `EXPIRED` | 제한 시간이 끝나 잠긴 상태. 타이머 모드에서는 정답자가 있을 수 있음 |
| `CLOSED` | 유지하지 않음 | 모든 게임 액션이 종료된 상태 |

### 5.1 준비와 시작

1. 방 생성 시 1라운드를 `PREPARING_KEYWORD`로 준비하고 제한 시간을 60초로 둔다.
2. 준비 중에는 모드와 관계없이 호스트 또는 진행자가 20~180초 범위의 5초 단위 값으로 제한 시간을 바꿀 수 있다.
3. 활성 라운드에서는 제한 시간을 바꿀 수 없다.
4. 준비 중 호스트 또는 진행자는 정답 판정 모드를 바꿀 수 있고, 활성 라운드에서는 바꿀 수 없다.
5. 현재 그리기 권한자가 `제시어 확정 및 시작`을 요청한다.
6. 서버는 발신 권한, 최소 시작 조건, 제시어 스키마를 검증한다.
7. 한 큐 작업에서 제시어 원문과 공백 제거 정규화 값을 저장하고 `hasKeyword=true`, `startedAt=serverNow`, `roundEndsAt=serverNow+durationSeconds*1000`, `guessLocked=false`로 설정한다.
8. 같은 작업에서 방을 `ROUND_ACTIVE`, 라운드를 `DRAWING_AND_GUESSING`으로 전이한다. 별도 시작 버튼이나 추가 시작 이벤트는 없다.

근거: 게임 설명 4·7·8행, D-05·D-06·D-21.

### 5.2 정답과 만료

- 서버는 방별 명령 큐에서 추측, 그림 변경, 권한 변경, 제한 시간 만료를 순차 처리한다.
- 각 그림·추측 요청을 처리할 때 서버 시각이 `roundEndsAt` 이상이면 먼저 `EXPIRED` 전이를 확정한다.
- `FIRST_CORRECT`는 최초 정답 한 건만 `winnerId`, `winnerNickname`, `solvedAt`에 기록하고 즉시 `SOLVED`로 잠근다.
- `UNTIL_TIMER`는 정답 내용을 `null`로 가려 공개하고 해당 사용자를 `correctPlayerIds`에 추가한 뒤 타이머까지 계속한다.
- 정답자는 각각 1점, 그림 담당자는 최초 정답 발생 시 한 번만 1점을 받는다.
- `EXPIRED` 전이는 `expiredAt`을 한 번만 기록하며 타이머 모드에서는 정답자 수가 0 이상일 수 있다.
- 두 종료 상태 모두 `guessLocked=true`, `drawingLocked=true`이며 이후 그림과 추측 요청을 서버가 거부한다.
- 마감 시각 전에 큐에서 수락·판정된 정답은 `SOLVED`가 되고, 그 뒤 실행되는 만료 작업은 아무 변화 없이 끝난다.
- 마감 시각 이상에 도착한 추측은 정답 문자열이어도 수락하지 않는다.

근거: 게임 설명 4행, D-21, 공통 지침 §1.2·§3.7.

### 5.3 대기실 복귀와 다음 라운드

- 호스트 또는 진행자는 활성·해결·만료 상태에서 방 전체를 대기실로 되돌릴 수 있다.
- 서버는 새 `roundId`를 만들고 방을 `WAITING`, 라운드를 `PREPARING_KEYWORD`로 전이한다.
- 기존 `drawerId`, 마지막 제한 시간, 정답 판정 모드, 모든 플레이어의 누적 점수는 유지한다.
- 제시어, 정답자, `keywordExposedPlayerIds`, `guessFeed`를 비우고 새 `drawingRevision`의 빈 캔버스를 만든다.
- 새 제시어 확정 전에는 그림과 추측을 받을 수 없다.

근거: D-07·D-21.

## 6. 제시어 정보 경계

- 제시어 원문과 정규화 값은 서버 전용 상태다.
- 현재 그리기 권한자와 진행자에게만 수신자별 PRIVATE 상태로 원문을 보낸다.
- 일반 참여자, 다른 방 사용자, 강퇴된 사용자에게는 제시어 원문이나 정규화 값을 보내지 않는다.
- PUBLIC 상태에는 `hasKeyword`만 포함한다.
- 제시어 가리기 버튼은 각 권한자 탭의 로컬 표시 상태만 바꾸며 서버 권한이나 다른 사용자의 화면을 바꾸지 않는다.
- 라운드에서 제시어를 받은 모든 플레이어 ID를 `keywordExposedPlayerIds`에 추가한다.
- 목록에 한 번 들어간 플레이어는 권한을 잃어도 해당 라운드가 끝날 때까지 추측할 수 없다.
- 로그, 분석 이벤트, 오류 메시지에 제시어를 기록하지 않는다.

근거: 게임 설명 7·8행, D-08·D-11·D-12, 공통 지침 §1.2·§2.4.

## 7. 추측과 정답

### 7.1 추측 자격

서버는 다음 조건을 모두 만족할 때만 추측을 수락한다.

- 방 상태가 `ROUND_ACTIVE`이고 라운드 상태가 `DRAWING_AND_GUESSING`이다.
- `guessLocked=false`이고 서버 시각이 `roundEndsAt` 전이다.
- 발신자가 해당 방의 연결된 플레이어다.
- 발신자는 진행자가 아니다.
- 발신자 ID가 `keywordExposedPlayerIds`에 없다.
- 타이머 모드에서 아직 정답을 맞히지 않았다.
- 추측은 1~80 Unicode code point이며 요청 페이로드는 512바이트 이하이다.
- 연결별 추측 제한인 초당 지속 4건·버스트 8건을 넘지 않는다.

### 7.2 정규화

`normalizeGuess(value)`는 JavaScript 정규식 의미의 모든 Unicode 공백 문자를 제거한다. 영문 대소문자, 문장부호, Unicode 조합 형태는 바꾸지 않는다.

```text
정답 여부 = normalizeGuess(추측) === normalizedKeyword
```

근거: 게임 설명 9행, D-09.

### 7.3 공개 추측 피드

- 서버가 정상 수락한 모든 추측에 방별 단조 증가 `guessSeq`를 부여한다.
- 공개 항목은 `guessId`, `roundId`, `guessSeq`, `playerId`, `nickname`, `text|string|null`, `submittedAt`, `isCorrect`다.
- 수락된 항목은 오답과 정답 모두 해당 방 전체에 순서대로 공유한다.
- 선착순 모드 정답은 원문을 `GUESS_SHARED`로 공유한 뒤 `ROUND_SOLVED`를 공유한다.
- 타이머 모드 정답은 `text:null`로 공유하고 다른 참가자의 추측을 계속 받는다.
- 권한 거부, 상태 거부, Rate Limit, 길이·스키마 오류처럼 수락되지 않은 데이터는 피드에 넣거나 방송하지 않는다.
- 서버는 현재 라운드의 최근 100개를 `guessFeed`에 유지하고 재접속자에게 복원한다. 101번째부터 가장 오래된 항목을 제거한다.

근거: 게임 설명 4행, D-10, 공통 지침 §3.7.

## 8. 벡터 캔버스

### 8.1 도구

| 구분 | 확정 값 |
|---|---|
| 펜 색상 | 검정 `#111827`, 파랑 `#0072B2`, 주황 `#E69F00`, 초록 `#009E73`, 버밀리언 `#D55E00`, 보라 `#7B2CBF` |
| 굵기 | `THIN=0.003`, `MEDIUM=0.007`, `THICK=0.014` |
| 도구 | `PEN`, `ERASER` |
| 편집 | 마지막 표시 스트로크 되돌리기, 전체 지우기 |

색은 고정 팔레트와 텍스트 라벨로 표시한다. 지우개도 좌표 스트로크로 저장하고 앞선 스트로크 위에 순서대로 합성한다.

### 8.2 스트로크 규칙

- 좌표는 캔버스 크기와 무관한 `0~1` 정규화 값이다.
- 현재 그리기 권한자의 `PEN` 또는 `ERASER` 스트로크만 서버가 수락한다.
- 모든 배치는 현재 `roundId`, `drawingRevision`, `drawerEpoch`와 일치해야 한다.
- 권한 지정·회수 때 `drawerEpoch`를 증가시키고 이전 epoch의 미완성 로컬 스트로크와 지연 배치를 폐기한다.
- 스트로크 배치당 점은 1~64개, 메시지는 8KiB 이하, 그리기 권한자 제한은 초당 지속 25배치·버스트 40배치다.
- 스트로크 하나는 최대 2,048점이다.
- 캔버스 하나는 최대 1,000 스트로크, 50,000점, 직렬화 크기 4MiB다.
- `roundId:drawingRevision:strokeId:batchSeq`를 중복 제거 키로 사용한다.
- 되돌리기는 가장 마지막에 표시 중인 완료 스트로크 하나를 `undone=true`로 만들며 다시 실행해도 같은 결과를 내야 한다.
- 전체 지우기는 `drawingRevision`을 증가시키고 스트로크·되돌리기 상태를 비운다. 이전 revision 배치는 모두 거부한다.
- 새 라운드도 `drawingRevision`을 증가시킨 빈 캔버스로 시작한다.
- 캔버스 전체 비트맵 프레임은 권위 상태나 반복 전송 데이터로 사용하지 않는다.

근거: 게임 설명 6행, D-12·D-13, 공통 지침 §1.2·§3.7.

## 9. 권한 지정과 회수

- `PREPARING_KEYWORD`에서는 호스트 또는 진행자가, `DRAWING_AND_GUESSING`에서는 진행자 모드의 진행자만 같은 방의 연결 참여자에게 그리기 권한을 지정하거나 회수할 수 있다.
- 지정과 회수는 현재 라운드 상태를 바꾸지 않고 기존 그림과 제시어를 유지한다.
- 서버는 `drawerId`를 한 번만 교체하고 `drawerEpoch`를 증가시킨다.
- 활성 라운드의 새 그리기 권한자에게 PRIVATE 제시어를 보내고 ID를 `keywordExposedPlayerIds`에 추가한다.
- 이전 그리기 권한자는 즉시 제시어·그림 관련 `allowedActions`를 잃고 미완성 로컬 스트로크를 폐기한다.
- 회수 대상은 진행자 자신이다.

근거: 게임 설명 8행, D-08·D-12.

## 10. 강퇴

- 호스트 또는 진행자만 같은 방의 다른 플레이어를 강퇴할 수 있다.
- 서버는 강퇴 대상의 연결을 닫고 플레이어 슬롯을 제거한다.
- 정규화한 닉네임과 복구 토큰 해시를 방의 차단 목록에 기록하며 방이 닫힐 때까지 재입장을 거부한다.
- 강퇴된 사용자의 기존 복구 토큰은 즉시 무효다.
- 대상에게 `KICKED`, 나머지 방 연결에 `PLAYER_KICKED`와 갱신된 공개 상태를 보낸다.
- 진행자 모드에서 강퇴 대상이 현재 그리기 권한자라면 같은 큐 작업에서 `drawerId=moderatorId`로 회수하고 `drawerEpoch`를 증가시킨다.
- 계정이 없으므로 새 탭과 새 닉네임으로 우회하는 것까지 보장해 차단하지는 않는다.
- 호스트 자신을 강퇴 대상으로 지정할 수 없으며 호스트 역할은 다른 사용자에게 넘어가지 않는다.

근거: 게임 설명 13·14행, D-14, 공통 지침 §3.7.

## 11. 서버 파생 `allowedActions`

클라이언트는 서버가 수신자별로 계산한 아래 액션만 활성화한다. 서버는 목록 포함 여부와 무관하게 모든 요청을 다시 검증한다.

| 액션 | 허용 조건 |
|---|---|
| `LEAVE_ROOM` | 연결된 방 멤버이며 방이 `CLOSED`가 아님 |
| `SET_ROUND_DURATION` | `WAITING/PREPARING_KEYWORD`, 모드와 관계없이 호스트 또는 진행자 |
| `SET_ANSWER_MODE` | `WAITING/PREPARING_KEYWORD`, 호스트 또는 진행자 |
| `SET_KEYWORD_AND_START` | `WAITING/PREPARING_KEYWORD`, 현재 `drawerId`, 최소 시작 조건 충족 |
| `DRAW_STROKE_BATCH` | `ROUND_ACTIVE`, 현재 `drawerId`, 마감 전, 캔버스 잠금 아님 |
| `UNDO_LAST_STROKE` | 위 그림 조건을 만족하고 표시 스트로크가 하나 이상 있음 |
| `CLEAR_DRAWING` | 위 그림 조건을 만족함 |
| `SUBMIT_GUESS` | `ROUND_ACTIVE`, 연결됨, 진행자 아님, 제시어 열람·정답 이력 없음, 마감 전 |
| `ASSIGN_DRAWER` | 준비 중 호스트/진행자 또는 활성 중 진행자 모드 진행자이며 대상이 연결됨 |
| `RECLAIM_DRAWER` | 준비 중 호스트/진행자 또는 활성 중 진행자 모드 진행자이며 자신이 현재 drawer가 아님 |
| `KICK_PLAYER` | 연결된 호스트 또는 진행자이며 유효한 다른 대상이 있음 |
| `START_NEXT_ROUND` | `ROUND_SOLVED` 또는 `ROUND_EXPIRED`, 일반 모드 호스트 또는 진행자 모드 진행자 |
| `RETURN_TO_WAITING` | 활성·해결·만료 상태의 호스트 또는 진행자 |

근거: 공통 지침 §1.2·§3.7과 게임 설명 4·8·13행.

## 13. 핵심 불변식

1. 다른 방의 플레이어·제시어·그림·추측·정답·종료 이벤트를 읽거나 변경할 수 없다.
2. `hostId`는 방 생성부터 종료까지 불변이며 연결 단절로 바뀌지 않는다.
3. 호스트 자동 이양 함수나 대체 후보 선택 로직은 존재하지 않는다.
4. 활성 라운드에는 현재 그리기 권한자가 정확히 한 명이다.
5. 제시어는 서버와 현재 그리기 권한자·진행자 외에는 전달되지 않는다.
6. `keywordExposedPlayerIds`에 포함된 사용자는 해당 라운드에서 추측할 수 없다.
7. 서버가 수락한 모든 추측만 `guessSeq` 순서로 방 전체에 공개된다.
8. 선착순 모드는 최초 정답 또는 시간 만료 중 하나만 라운드를 종료하고, 타이머 모드는 정답 유무와 관계없이 시간 만료까지 진행한다.
9. `SOLVED`와 `EXPIRED` 이후 그림과 추측은 서버와 클라이언트 양쪽에서 잠긴다.
10. 활성 라운드의 `roundEndsAt`과 `durationSeconds`는 바뀌지 않는다.
11. 그림 권위 데이터는 정규화 좌표의 벡터 스트로크다.
12. 모든 권한·상태·입력 크기·Rate Limit 검증은 서버에서 수행한다.
13. 점수는 라운드와 정답 모드 변경으로 초기화되지 않으며 방이 사라질 때 함께 소멸한다.
