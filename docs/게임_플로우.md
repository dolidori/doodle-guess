# Doodle Guess 게임 플로우

## 1. 문서 기준

- 규칙은 `게임_규칙_문서.md`, 상태 필드와 제약은 `게임_상태_설계.json`, 통신 이벤트는 `WebSocket_이벤트_명세.md`를 따른다.
- 확정 결정은 `결정_기록.md` D-01~D-24를 따른다.
- 모든 전이는 서버가 방별 명령 큐에서 검증·확정한 뒤 해당 방에만 공유한다. 근거: 공통 지침 §1.2·§3.7.
- 호스트 연결 단절로 역할이나 `hostId`를 바꾸는 전이는 존재하지 않는다. 근거: 게임 설명 14행, D-17.

## 2. 전체 상태 흐름

```text
방 생성
  |
  v
WAITING / PREPARING_KEYWORD
  |  현재 drawer가 제시어 확정 및 시작
  |  조건: 연결 drawer 1명 + 연결된 추측 가능자 1명 이상
  v
ROUND_ACTIVE / DRAWING_AND_GUESSING
  | \
  |  \ roundEndsAt 도달
  |   v
  |  ROUND_EXPIRED / EXPIRED
  |
  +---- 최초 정답
       v
     ROUND_SOLVED / SOLVED

ROUND_SOLVED 또는 ROUND_EXPIRED
  |  일반 모드 host / 진행자 모드 moderator가 다음 라운드 준비
  v
WAITING / PREPARING_KEYWORD

모든 열린 상태
  |  host 명시 퇴장 / host 30분 미복귀 / 서버 재시작
  v
CLOSED
```

종료 분기는 `SOLVED`와 `EXPIRED` 중 정확히 하나만 확정한다. 그림·추측 처리 시 서버 시각이 `roundEndsAt` 이상이면 만료를 먼저 확정한다.

## 3. 일반 모드

### 3.1 방 만들기와 입장

```text
호스트
  -> NORMAL 방 생성 요청
서버
  -> 100~999 중 미사용 번호 원자 예약
  -> host 슬롯 생성(isHost=true, isModerator=false)
  -> hostId=drawerId=생성자
  -> round 1 PREPARING_KEYWORD, 제한 시간 60초
  -> 탭별 복구 토큰 발급
참여자
  -> 3자리 숫자 방번호와 닉네임 입력
  -> Enter로 입장
서버
  -> 형식·차단 목록·중복 닉네임·30명 정원 검증
  -> 승인된 한 요청씩 슬롯 추가
```

근거: 게임 설명 2·3·5·10~12행, D-02~D-05, 공통 지침 §2.3.

### 3.2 라운드 시작

```text
host가 20~180초, 5초 단위 제한 시간 설정
  -> 활성 라운드 전에는 변경 가능
host가 제시어 입력 후 "확정 및 시작"
  -> 서버가 host==drawerId 검증
  -> 연결된 추측 가능자 1명 이상 검증
  -> keyword/normalizedKeyword SERVER_PRIVATE 저장
  -> keywordExposedPlayerIds에 host 추가
  -> startedAt=serverNow
  -> roundEndsAt=serverNow+durationSeconds*1000
  -> ROUND_ACTIVE 원자 전이
```

별도 시작 버튼은 없다. 근거: D-05·D-06·D-21.

### 3.3 진행과 종료

```text
host(drawer) -> 벡터 스트로크 배치
서버 -> 권한·roundId·revision·epoch·좌표·크기·Rate Limit 검증
서버 -> 같은 방 참여자에게 수락 배치 공유

추측자 -> 추측 제출
서버 -> 자격·시간·길이·Rate Limit 검증
서버 -> guessSeq 부여 후 GUESS_SHARED
  ├─ 오답: ROUND_ACTIVE 유지
  └─ 정답: 같은 큐 작업에서 ROUND_SOLVED, 그림·추측 잠금

타이머 -> roundEndsAt 도달
서버 -> 아직 활성일 때 ROUND_EXPIRED, 그림·추측 잠금
```

정답과 만료 후 host만 다음 라운드를 준비한다. 기존 `drawerId`와 제한 시간은 유지하고 제시어·그림·추측 피드는 새 라운드 값으로 초기화한다.

근거: 게임 설명 4·6·9행, D-07·D-09·D-10·D-13·D-21.

## 4. 진행자 모드

### 4.1 생성과 초기 상태

```text
진행자 -> MODERATOR 방 생성
서버
  -> 생성자 isHost=true, isModerator=true
  -> hostId=moderatorId=drawerId=생성자
  -> 방 수명 동안 mode=MODERATOR 고정
```

진행자는 30명 정원에 포함되며 항상 PRIVATE 제시어를 볼 수 있다. 근거: 게임 설명 8행, D-03·D-04.

### 4.2 그리기 권한 지정

```text
진행자 -> 연결 참여자에게 ASSIGN_DRAWER
서버
  -> 진행자 권한과 같은 방 대상 검증
  -> drawerId 교체
  -> drawerEpoch 증가
  -> 이전 drawer의 미완성 로컬 스트로크·지연 배치 무효
  -> 새 drawer에게 PRIVATE 제시어 전송
  -> keywordExposedPlayerIds에 새 drawer 추가
  -> 기존 그림·제시어·라운드 상태 유지
```

PREPARING 상태에서 지정받은 drawer가 제시어를 확정해 라운드를 시작한다. 활성 상태에서 지정하면 기존 제시어와 그림을 이어서 그린다.

### 4.3 권한 회수

```text
진행자 -> RECLAIM_DRAWER
서버
  -> drawerId=moderatorId
  -> drawerEpoch 증가
  -> 이전 drawer의 그림·제시어 allowedActions 제거
  -> 진행자 그림 allowedActions 활성화
```

권한을 잃은 사용자는 이후 PRIVATE 제시어를 받지 않지만 이미 본 제시어 때문에 현재 라운드 추측 자격은 얻지 못한다.

### 4.4 제한 시간과 다음 라운드

- 준비 상태에서는 모드와 관계없이 호스트 또는 진행자가 제한 시간을 설정한다.
- 활성 상태에서는 진행자를 포함해 누구도 제한 시간을 바꿀 수 없다.
- 정답 또는 만료 후 진행자만 다음 라운드를 준비한다.
- 다음 라운드에도 현재 `drawerId`와 마지막 제한 시간을 유지한다.

근거: 게임 설명 8행, D-07·D-08·D-12·D-21.

## 5. 추측 공개와 최초 정답 경합

```text
SUBMIT_GUESS 도착
  |
  v
방별 명령 큐
  |
  +-- now >= roundEndsAt ----------> EXPIRED 확정 -> ROUND_EXPIRED 거부
  |
  +-- 자격/스키마/Rate Limit 실패 -> 거부, guessFeed에 넣지 않음
  |
  v
guessSeq 증가 + guessFeed 추가 + GUESS_SHARED
  |
  +-- normalizedGuess 불일치 -----> ACTIVE 유지
  |
  v
status=SOLVED, winner 1회 기록, guessLocked/drawingLocked
  |
  v
ROUND_SOLVED 공유
```

- 수락된 정답 추측도 먼저 공개 추측 피드에 들어간다.
- 동시에 같은 정답이 도착해도 먼저 큐에서 수락된 한 명만 정답자다.
- 이후 요청은 `ROUND_LOCKED` 또는 `ROUND_EXPIRED`로 거부한다.
- 클라이언트는 `roundId`와 이벤트 `seq`로 정답 모달 중복 표시를 막는다.

근거: 게임 설명 4·9행, D-09·D-10, 공통 지침 §1.2·§3.7.

## 6. 캔버스 흐름

### 6.1 스트로크

```text
Pointer 입력
  -> 로컬 미리보기
  -> 1~64개 정규화 점 배치
  -> DRAW_STROKE_BATCH
서버
  -> drawerId, active, deadline 검증
  -> roundId/revision/epoch 검증
  -> tool/color/width/좌표/크기/Rate Limit 검증
  -> dedupe key 검증
  -> drawingSeq 증가
  -> 방 전체 수락 배치 공유
```

- 도구는 다색 `PEN`과 스트로크 합성형 `ERASER`다.
- 굵기는 `THIN`, `MEDIUM`, `THICK` 세 단계다.
- 마지막 표시 스트로크 되돌리기와 전체 지우기는 서버 명령으로 처리한다.
- 전체 지우기와 새 라운드는 `drawingRevision`을 올려 이전 지연 배치를 무효화한다.

### 6.2 재접속 그림 복원

```text
재접속 승인
  -> PUBLIC_STATE: drawingRevision, drawingSeq, drawerEpoch, 한계 메타데이터
  -> DRAWING_SNAPSHOT_META
  -> 최대 64KiB 단위 스냅샷 청크
  -> sha256 검증
  -> 마지막 snapshot seq 뒤 증분 배치 적용
```

권위 원본은 항상 벡터 스트로크다. 근거: 게임 설명 6행, D-13.

## 7. 연결 단절과 복구

### 7.1 일반 참여자

```text
연결 끊김
  -> connected=false
  -> 슬롯·역할·keywordExposed 이력 유지

같은 탭 복귀
  -> sessionStorage 복구 토큰으로 기존 슬롯 복원

토큰 없는 같은 닉네임 복귀
  -> 동일 닉네임의 disconnected 슬롯 복원

다른 닉네임 입장
  -> 정원이 남으면 새 슬롯 생성
```

재접속 응답은 현재 방·라운드·플레이어·`allowedActions`·최근 100개 `guessFeed`·그림 스냅샷을 즉시 복원한다. 제시어는 현재 drawer 또는 moderator에게만 PRIVATE로 복원한다.

근거: 게임 설명 13행, D-15·D-16, 공통 지침 §2.3.

### 7.2 호스트

```text
host 연결 끊김
  -> connected=false
  -> isHost/hostId/drawerId 유지
  -> hostDisconnectedAt=serverNow
  -> expiresAt=serverNow+30분
  -> 자동 이양 없음

30분 안에 복귀
  -> 복구 토큰 우선, 원래 닉네임 폴백
  -> 기존 host 슬롯 연결 교체
  -> 종료 작업 취소

30분 만료
  -> ROOM_CLOSED(HOST_RECONNECT_TIMEOUT)
  -> 모든 연결 종료
```

- 일반 모드에서 호스트가 활성 라운드 중 끊겨도 참가자는 기존 그림을 보고 마감 전까지 추측할 수 있다.
- 호스트가 없으면 새 라운드를 준비하거나 제한 시간을 바꿀 수 없다.
- 진행자 모드 생성자는 호스트이자 진행자이므로 같은 30분 정책을 적용한다.

근거: 게임 설명 14행, D-16·D-17. 공통 지침 §2.6의 자동 이양은 적용하지 않는다.

## 8. 강퇴

```text
host 또는 moderator -> KICK_PLAYER
서버
  -> 발신자 권한·같은 방 대상·자기 자신 아님 검증
  -> 대상 연결 종료 및 슬롯 제거
  -> nickname + sessionTokenHash 차단 목록 추가
  -> 대상이 진행자 모드 drawer면 moderator에게 drawer 원자 회수
  -> 대상에게 KICKED
  -> 나머지 방 연결에 PLAYER_KICKED와 PUBLIC_STATE

강퇴 사용자 재입장
  -> 닉네임 또는 세션 토큰 해시 일치
  -> REENTRY_BLOCKED
```

계정이 없으므로 새 탭과 새 닉네임을 이용한 우회는 차단 보장 범위 밖이다. 근거: 게임 설명 13행, D-14.

## 9. 재접속 복원 화면

| 복원 상태 | 서버 상태 | 즉시 표시할 UI |
|---|---|---|
| 제시어 준비 | `WAITING/PREPARING_KEYWORD` | 현재 역할, 제한 시간, drawer면 제시어 입력, host/moderator면 시간 설정 |
| 진행 중 drawer | `ROUND_ACTIVE`, 본인=`drawerId` | PRIVATE 제시어, 가리기, 도구, 남은 시간 |
| 진행 중 추측자 | `ROUND_ACTIVE`, 추측 자격 있음 | 캔버스, 최근 추측 피드, 추측 입력, 남은 시간 |
| 진행 중 제시어 열람자 | `ROUND_ACTIVE`, ID가 `keywordExposedPlayerIds`에 있음 | 캔버스와 PRIVATE 권한에 따른 제시어, 추측 입력 없음 |
| 정답 완료 | `ROUND_SOLVED` | 잠긴 캔버스·입력, 정답자, 중복 없는 정답 모달 |
| 시간 만료 | `ROUND_EXPIRED` | 잠긴 캔버스·입력, 시간 만료 안내 |
| 호스트 부재 | `hostDisconnectedAt` 존재 | 비이양 상태와 방 종료 예정 시각 |
| 강퇴 | 차단 목록 일치 | 재입장 불가 안내 |

근거: 공통 지침 §2.3, 게임 설명 4·7·8·13·14행.
