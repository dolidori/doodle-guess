# Doodle Guess 화면설계서

## 1. 문서 계약

- 게임명은 `Doodle Guess`, 한글 보조 표기는 `두들 게스`다.
- 규칙은 `게임_규칙_문서.md`, 데이터 구조는 `게임_상태_설계.json`, 통신 이벤트와 오류 코드는 `WebSocket_이벤트_명세.md`를 단일 출처로 사용한다.
- 클라이언트는 서버가 수신자별로 계산한 `allowedActions`만으로 조작 가능 여부를 표시한다. 버튼을 활성화한 뒤에도 서버 검증 결과가 최종 권위다.
- 제시어 원문은 현재 라운드에서 제시어 열람 권한이 있는 사용자에게만 PRIVATE 상태로 전달한다. 공개 상태, 추측 피드, 로그에는 포함하지 않는다.
- 서버가 수락한 모든 추측은 제출자 닉네임과 방 안 순번을 포함해 같은 방 참여자 모두에게 공개한다.
- 호스트 또는 진행자는 라운드 시작 전에 제한 시간을 20~180초 범위에서 5초 단위로 정하며 기본값은 60초다. 시작 뒤에는 바꿀 수 없고 서버 `roundEndsAt`가 시간 표시와 만료의 권위다.

[근거: 게임 설명 1~14행, 결정 D-01~D-19, 공통 지침 §1.2·§4.8]

## 2. 공통 화면 구조

```text
GameApp
├─ LobbyScreen
└─ RoomShell
   ├─ GameHeader
   ├─ ConnectionBanner
   ├─ PlayerPanel
   ├─ CanvasStage
   ├─ RolePanel
   │  ├─ KeywordPanel
   │  ├─ DrawingToolbar
   │  ├─ GuessComposer
   │  └─ ModeratorControls
   ├─ GuessFeed
   ├─ ToastViewport
   ├─ ModalViewport
   └─ BlockingOverlay
```

`RoomShell`은 방 안의 모든 화면에서 유지한다. 역할이나 라운드 상태가 바뀌어도 캔버스와 공개 추측 피드를 재마운트하지 않고, 서버 스냅샷 기준으로 내용만 갱신한다.

### 2.1 고정 헤더

- 방번호 `100~999`: 버튼으로 표시하고 누르면 중앙 확대 모달을 연다.
- 내 닉네임과 역할: `호스트`, `진행자`, `그리기`, `추측` 배지를 조합해 표시한다.
- 라운드 상태: `제시어 준비`, `그리는 중`, `정답 확정`, `시간 종료`의 한국어 표기를 사용한다.
- 진행 중 제한 시간: `MM:SS`로 표시하고 숫자 폭을 고정한다.
- 연결 상태: 연결됨, 재연결 중, 연결 실패를 색·아이콘·텍스트 대체 라벨로 표현한다.
- 음소거와 나가기: 음소거는 전역 로컬 설정, 나가기는 방을 떠나는 확인 모달을 연다.
- 모바일에서는 게임명 로고를 숨기고 방번호·내 역할·나가기 조작을 보존한다.

### 2.2 알림 계층

| 계층 | 용도 | 동작 |
|---|---|---|
| 차단 오버레이 | 재접속, 서버 재시작, 강퇴, 호스트 30분 미복귀 종료 | 아래 조작을 모두 차단 |
| 결정 모달 | 전체 지우기 확인, 방 나가기 확인 | 포커스를 모달 안에 가둠 |
| 이벤트 모달 | 정답자 발표, 시간 종료 | 종류와 `roundId` 조합당 한 번만 큐에 추가 |
| 지속 배너 | 호스트 부재와 남은 시간, 해결된 라운드 | 게임 화면을 가리지 않음 |
| 토스트 | 재연결 성공, 서버 검증 실패, 권한 변경 | FIFO, 짧은 비차단 알림 |

### 2.3 역할·단계별 `allowedActions`

| 사용자 상태 | `PREPARING_KEYWORD` | `DRAWING_AND_GUESSING` | `SOLVED`·`EXPIRED` |
|---|---|---|---|
| 일반 모드 호스트 겸 drawer | `SET_ROUND_DURATION`, `SET_KEYWORD_AND_START`, `KICK_PLAYER`, `LEAVE_ROOM` | `DRAW_STROKE_BATCH`, `UNDO_LAST_STROKE`, `CLEAR_DRAWING`, `KICK_PLAYER`, `LEAVE_ROOM` | `START_NEXT_ROUND`, `KICK_PLAYER`, `LEAVE_ROOM` |
| 진행자 모드 호스트 겸 진행자, drawer 아님 | `SET_ROUND_DURATION`, `ASSIGN_DRAWER`, `RECLAIM_DRAWER`, `KICK_PLAYER`, `LEAVE_ROOM` | `ASSIGN_DRAWER`, `RECLAIM_DRAWER`, `KICK_PLAYER`, `LEAVE_ROOM` | `START_NEXT_ROUND`, `KICK_PLAYER`, `LEAVE_ROOM` |
| 진행자 모드 호스트 겸 진행자 겸 drawer | 위 행에 `SET_KEYWORD_AND_START` 추가 | 위 행에 `DRAW_STROKE_BATCH`, `UNDO_LAST_STROKE`, `CLEAR_DRAWING` 추가 | 위 행과 동일 |
| 위임받은 현재 drawer | `SET_KEYWORD_AND_START`, `LEAVE_ROOM` | `DRAW_STROKE_BATCH`, `UNDO_LAST_STROKE`, `CLEAR_DRAWING`, `LEAVE_ROOM` | `LEAVE_ROOM` |
| 제시어를 보지 않은 추측 자격자 | `LEAVE_ROOM` | `SUBMIT_GUESS`, `LEAVE_ROOM` | `LEAVE_ROOM` |
| 현재 라운드에서 제시어를 본 이전 drawer | `LEAVE_ROOM` | `LEAVE_ROOM` | `LEAVE_ROOM` |
| 연결 끊김·재접속 중·강퇴 대상 | 없음 | 없음 | 없음 |

- `DRAW_STROKE_BATCH`가 펜과 지우개 입력을 모두 허용한다.
- `SET_ROUND_DURATION`은 host 또는 moderator에게만 있으며 drawer 권한만으로는 생기지 않는다.
- PUBLIC phase가 진행 또는 최종 상태가 되면 제한 시간 slider는 disabled이고 변경 불가 사유가 보인다.
- 호스트 연결이 끊기면 자동 이양 없이 호스트 전용 action이 모든 연결 사용자에게서 빠진다.

[근거: 게임 설명 4~8행·13~14행, 결정 D-04~D-08·D-12~D-17, 대표님 추가 결정 — 라운드 제한 시간]

## 3. 화면별 설계

### S-01 로비

#### 목적

방을 만들거나 기존 방에 입장하는 실제 시작 화면이다.

#### 구성

- 브랜드: `Doodle Guess`와 `두들 게스`
- 서버 연결 상태 점: 시각적으로는 작은 점, 접근성 이름은 `서버 연결됨`, `서버 연결 중`, `서버 연결 끊김`
- 닉네임 입력
- 3자리 방번호 입력: `inputMode="numeric"`, `pattern="[0-9]*"`, 정확히 `100~999`
- `입장하기` 버튼과 Enter 제출
- `방 만들기`: 일반 모드 또는 진행자 모드를 명시해 생성
- 최근 접속 목록: 최신순 최대 10개, 항목을 누르면 닉네임과 방번호만 채우며 자동 입장하지 않음

#### 로비 intent 활성 조건

- 연결됨: `CREATE_ROOM`, 유효한 입력일 때 `JOIN_ROOM` 전송 가능
- 연결 중·끊김: 두 intent 모두 비활성

[근거: 게임 설명 2~3행·10~12행, 결정 D-02~D-04, 공통 지침 §4.12]

### S-02 제시어 준비

#### 공통 구성

- 이전 라운드 그림은 다음 제시어 준비 진입 시 비운 상태로 표시한다.
- 현재 drawer에게 제시어 입력과 `제시어 확정 및 시작` 버튼을 제공한다.
- 버튼 한 번으로 제시어 저장과 라운드 시작을 원자 처리한다.
- 호스트 또는 진행자에게 `min="20"`, `max="180"`, `step="5"`인 제한 시간 range input을 제공하고 기본 60초를 표시한다. 현재 값은 `1분 30초`와 같은 자연어로 슬라이더 옆에 표시한다. 위임받은 drawer는 설정된 시간을 읽기 전용으로 본다.
- 새 방의 최초값은 60초이며 다음 라운드는 마지막으로 서버가 확정한 설정값을 유지한다.
- range input에는 연결된 `제한 시간` 이름과 현재 자연어 값을 담은 `aria-valuetext`를 제공한다. 키보드 화살표로 5초씩 조절되며 슬라이더 조작 영역의 최소 높이는 44px다.
- 제한 시간 변경은 제시어 준비 상태에서만 가능하다. 진행 상태에서는 같은 위치에 disabled 슬라이더와 `라운드 진행 중에는 제한 시간을 바꿀 수 없습니다`를 표시한다.
- 제시어는 빈 문자열과 공백만 있는 값을 허용하지 않는다.
- 연결된 drawer 1명과 추측 자격자 1명 이상이 아니면 시작 버튼을 비활성화하고 이유를 표시한다.
- 일반 참여자는 `그리기 사용자가 제시어를 준비하고 있습니다` 상태를 본다.

#### 역할별 `allowedActions`

| 역할 | 허용 액션 |
|---|---|
| 일반 모드 호스트 겸 drawer | `SET_ROUND_DURATION`, `SET_KEYWORD_AND_START`, `KICK_PLAYER`, `LEAVE_ROOM` |
| 진행자 모드 진행자 겸 drawer | `SET_ROUND_DURATION`, `SET_KEYWORD_AND_START`, `ASSIGN_DRAWER`, `KICK_PLAYER`, `LEAVE_ROOM` |
| 위임받은 drawer | `SET_KEYWORD_AND_START`, `LEAVE_ROOM` |
| 추측 참여자 | `LEAVE_ROOM` |

[근거: 게임 설명 4~5행·7~8행, 결정 D-04~D-06]

### S-03 일반 모드 호스트 그리기 화면

- 헤더에 `호스트 · 그리기` 배지를 표시한다.
- PRIVATE 제시어 패널은 기본 가림 상태로 시작한다.
- `제시어 보기`를 누르면 현재 탭에서만 원문을 표시하고 `제시어 가리기`로 되돌린다.
- 보기 상태는 서버로 전송하지 않으며 새로고침·재접속 시 다시 가림 상태가 된다.
- 캔버스와 고정 다색 팔레트, 펜·지우개, 굵기 3단계, 되돌리기, 전체 지우기를 제공한다.
- 공개 추측 피드는 캔버스 옆 또는 아래에서 계속 보인다.
- 서버 `roundEndsAt` 기준 카운트다운을 캔버스 상단에 계속 표시한다.

`allowedActions`: `DRAW_STROKE_BATCH`, `UNDO_LAST_STROKE`, `CLEAR_DRAWING`, `KICK_PLAYER`, `LEAVE_ROOM`. 펜과 `tool: "ERASER"` 지우개 스트로크를 같은 이벤트로 전송한다.

[근거: 게임 설명 4~7행·13행, 결정 D-08·D-11·D-13]

### S-04 일반 추측자 화면

- 캔버스를 가장 큰 영역으로 표시한다.
- 공개 추측 피드에는 서버가 수락한 추측만 `순번 · 닉네임 · 내용`으로 표시한다.
- 서버 `roundEndsAt` 기준 카운트다운을 그림과 입력 사이의 고정 위치에 표시한다.
- 입력값은 제출 성공 후 비운다. 서버 거부 시 입력값을 유지하고 이유를 인라인으로 표시한다.
- 정답 확정 전까지 `SUBMIT_GUESS`가 있을 때만 입력·제출을 활성화한다.
- 제시어 원문, 정규화 값, 제시어 가림 UI는 DOM에 만들지 않는다.

`allowedActions`: 라운드 진행 중 `SUBMIT_GUESS`, 항상 `LEAVE_ROOM`.

[근거: 게임 설명 4행·7행·9행, 결정 D-08~D-10]

### S-05 진행자 제어 화면

- 데스크톱에서는 참가자 패널, 캔버스, 진행 제어 패널의 3열 구조를 사용한다.
- 현재 drawer를 참가자 목록과 제어 패널 양쪽에 명시한다.
- 연결된 추측 자격자에게 `그리기 권한 주기`, 현재 drawer가 진행자가 아닐 때 `그리기 권한 가져오기`를 제공한다.
- drawer 변경 전 미완성 로컬 스트로크는 폐기되며 기존 확정 그림과 제시어는 유지된다는 문구를 제어 영역에 표시한다.
- 진행자는 PRIVATE 제시어를 열람할 수 있으나 기본은 로컬 가림이다.
- 진행자는 해당 라운드에 추측할 수 없다.
- 제한 시간은 준비 상태에서만 바꿀 수 있다. 진행 중에는 disabled slider와 `라운드 진행 중에는 제한 시간을 바꿀 수 없습니다`, 현재 카운트다운을 함께 본다.
- 참가자별 연결 상태와 `내보내기` 버튼을 표시한다.

`allowedActions`: 준비 중 `SET_ROUND_DURATION`; 전체 상태에서 권한과 단계가 맞을 때 `ASSIGN_DRAWER`, `RECLAIM_DRAWER`, `KICK_PLAYER`, `START_NEXT_ROUND`; 진행자 자신이 drawer일 때 `SET_KEYWORD_AND_START`와 그리기 액션.

[근거: 게임 설명 8행·13행, 결정 D-04·D-07·D-08·D-11·D-12]

### S-06 위임받은 그리기 사용자 화면

- `그리기 권한을 받았습니다` 토스트 후 drawer 화면으로 전환한다.
- 제시어 준비 상태에서는 제시어 입력과 확정·시작이 활성화된다.
- 진행 중에는 PRIVATE 제시어와 전체 그리기 도구가 활성화된다.
- 이 사용자에게 진행자 제어와 강퇴 기능은 표시하지 않는다.
- 권한 회수 즉시 진행 중 포인터 스트로크를 폐기하고 캔버스를 관람 상태로 바꾼다.
- 한 번 제시어를 본 사용자는 해당 라운드가 끝날 때까지 추측 입력을 받지 않는다.

`allowedActions`: 준비 중 `SET_KEYWORD_AND_START`; 진행 중 그리기 액션; 항상 `LEAVE_ROOM`.

[근거: 게임 설명 8행, 결정 D-08·D-12·D-13]

### S-07 공개 추측 피드

- 항목 형식: `#순번 닉네임: 추측 내용`.
- `guessSeq`는 현재 라운드의 서버 수락 순서를 나타내며 화면 정렬도 오름차순이다.
- 정답 추측 항목은 `정답` 텍스트 배지와 굵은 선으로 강조한다. 색상만으로 구분하지 않는다.
- 새 항목은 사용자가 피드 끝 근처에 있을 때만 자동 스크롤한다. 과거 항목을 읽는 중이면 `새 추측 N개` 버튼을 표시한다.
- 재접속 `PUBLIC_STATE`의 최근 추측 최대 100개를 먼저 복원하고 이후 `GUESS_SHARED`를 `guessSeq` 순서로 이어 붙인다.
- 권한 없음, 형식 오류, Rate Limit 초과 등 서버가 수락하지 않은 문자열은 피드에 넣지 않는다.
- 제시어와 서버 정규화 값은 절대 넣지 않는다.

[근거: 결정 D-09·D-10, 공통 지침 §1.2·§3.7]

### S-08 정답 확정 화면

- `ROUND_SOLVED`를 처음 수신하면 추측 입력과 캔버스 조작을 즉시 비활성화한다.
- 정답자의 닉네임을 정답자 모달로 표시한다.
- 모달 키는 `round-solved:{eventId}`이며 같은 키는 큐에 한 번만 들어간다.
- 모달을 닫은 뒤에도 `정답 확정 · {winnerNickname}` 배너와 잠긴 입력이 유지된다.
- 일반 모드는 호스트, 진행자 모드는 진행자에게만 `다음 라운드` 버튼을 표시한다.
- 다음 라운드 진입 시 drawer는 유지되고 캔버스·공개 추측 피드는 새 라운드 상태로 초기화된다.

[근거: 게임 설명 4행, 결정 D-07·D-10, `PLANNING_PROMPT` 핵심 불변식 5~6]

### S-08A 시간 종료 화면

- 서버 `ROUND_EXPIRED`를 수신하면 추측 입력과 캔버스 조작을 즉시 비활성화한다.
- `시간이 종료되었습니다` 모달은 `round-expired:{eventId}` 키로 한 번만 표시한다.
- 정답자 모달의 색·제목·아이콘을 재사용하지 않고 중립적인 시계 아이콘과 `시간 종료` 제목을 사용한다.
- 모달을 닫은 뒤에도 `시간 종료 · 다음 라운드를 기다리는 중` 배너와 `00:00` 타이머를 유지한다.
- 일반 모드는 호스트, 진행자 모드는 진행자에게만 `다음 라운드`를 제공한다.
- `ROUND_SOLVED`와 `ROUND_EXPIRED`는 같은 라운드의 최종 상태로 동시에 적용하지 않는다. 서버 `eventSeq`와 안정적인 `eventId`로 확정된 최종 이벤트만 반영한다.

[근거: 대표님 추가 결정 — 라운드 제한 시간, 공통 지침 §1.2·§3.8]

### S-09 호스트 부재

- 호스트 연결이 끊겨도 다른 사용자에게 호스트 배지를 주지 않는다.
- 모든 연결 사용자에게 `호스트 연결이 끊겼습니다 · 방 종료까지 MM:SS` 지속 배너를 표시한다.
- 서버가 제공한 종료 시각으로 남은 시간을 표시하며 클라이언트 시간이 권위가 되지 않는다.
- 현재 라운드에서 각 사용자에게 이미 허용된 추측·그리기는 계속한다.
- 호스트만 실행할 수 있는 다음 라운드·강퇴 기능은 `allowedActions`에서 빠지며 비활성 이유를 표시한다.
- 30분 안에 원래 호스트가 복귀하면 배너를 제거하고 `호스트가 재접속했습니다` 토스트를 표시한다.
- 30분이 지나면 `호스트가 돌아오지 않아 방이 종료되었습니다` 차단 오버레이를 표시하고 로비로 이동시킨다.

[근거: 게임 설명 14행, 결정 D-16·D-17]

### S-10 재접속

| 연결 상태 | 표시와 조작 |
|---|---|
| `CONNECTED` | 오버레이 없음 |
| `RECONNECTING` | `재연결 중 · 시도 n회` 차단 오버레이 |
| `RECONNECTED` | 서버 스냅샷 복원 후 `재연결되었습니다` 토스트 |
| `FAILED` | `연결 실패`와 `다시 연결`, `로비로 나가기` |

- 탭별 `sessionStorage` 복구 토큰을 우선 사용한다.
- 토큰이 없고 원래 닉네임 슬롯이 연결 끊김 상태면 같은 닉네임 복구를 시도한다.
- 이미 연결된 닉네임, 강퇴된 토큰·닉네임은 오류 화면으로 분기한다.
- 복원 순서는 PUBLIC 스냅샷, PRIVATE 스냅샷, `allowedActions`, 그림, 최근 추측 피드, 모달 중복 키다.
- 복원 스냅샷의 `roundEndsAt`와 서버 시간 오프셋으로 카운트다운을 즉시 재계산한다. 백그라운드 체류 시간을 로컬에서 멈추거나 더하지 않는다.
- drawer 복귀 시 그리기 UI를 즉시 복원하고 제시어는 로컬 가림 상태로 시작한다.

[근거: 게임 설명 13~14행, 결정 D-14~D-16, 공통 지침 §2.3·§5.4]

### S-11 강퇴 및 서버 재시작

- 강퇴된 사용자는 `방에서 내보내졌습니다` 차단 화면만 보고 게임 데이터는 즉시 폐기한다.
- 같은 방이 살아 있는 동안 같은 복구 토큰과 닉네임으로의 재입장 버튼을 제공하지 않는다.
- 서버 재시작으로 방이 사라졌으면 `서버가 다시 시작되어 기존 방이 종료되었습니다`를 표시하고 로비로 이동한다.
- 호스트가 명시적으로 방을 나가 닫힌 경우 남은 사용자에게 `호스트가 나가 방이 종료되었습니다`를 표시한다.

[근거: 게임 설명 13행, 결정 D-14·D-18]

## 4. 반응형 레이아웃

| 환경 | 레이아웃 |
|---|---|
| 모바일 세로, `0~640px` | 축약 헤더, 상태 행, 캔버스, 역할 패널, 하단 추측 입력. 참가자와 피드는 탭형 보조 패널 |
| 모바일 가로, 높이 `500px` 이하 | 좌측 참가자 축약 패널, 중앙 캔버스, 우측 역할 패널. 헤더 높이 축소 |
| 태블릿, `641~1023px` | 중앙 캔버스와 우측 역할 패널의 2열, 참가자·피드는 접이식 패널 |
| 데스크톱, `1024px` 이상 | 좌측 참가자, 중앙 캔버스, 우측 역할·추측 피드의 3열 |

- 전체 앱 높이는 `100dvh`, 대체값은 `100vh`다.
- 캔버스는 남은 공간 안에서 가장 큰 사각형을 차지하며 최소 조작 영역을 침범하지 않는다.
- 모바일 가상 키보드가 열리면 `visualViewport.height`로 하단 추측 입력을 키보드 위에 유지한다.
- 하단 조작부에는 `padding-bottom: max(var(--space-3), env(safe-area-inset-bottom))`과 `flex-shrink: 0`을 적용한다.
- 노치 방향이 바뀌어도 좌우 패널에 `safe-area-inset-left/right`를 반영한다.
- 페이지 스크롤은 잠그고 참가자 목록과 추측 피드만 독립 스크롤한다.
- 캔버스에만 `touch-action: none`, 폼과 버튼에는 `touch-action: manipulation`을 적용한다.

## 5. 타이머 표시와 경고

- 서버 스냅샷의 `roundEndsAt`와 `/api/time` 왕복 측정의 최소 RTT 샘플, `performance.now()` anchor로 추정한 서버 현재 시각을 사용해 남은 시간을 표시한다.
- 표시 초는 `Math.max(0, Math.ceil(remainingMs/1000))`으로 통일한다. `requestAnimationFrame` 또는 짧은 화면 갱신 scheduler는 앱 전체에 하나만 두고 표현만 갱신하며 만료 이벤트를 만들지 않는다.
- 남은 시간이 10초 이하가 되는 순간 `10초 남았습니다`를 시각 배너와 `aria-live="assertive"`로 한 번 알린다.
- 이후 매초를 스크린 리더에 읽지 않는다. 화면 숫자와 프로그레스 바만 갱신한다.
- 10초 이하에서는 `시간 얼마 남지 않음` 텍스트·굵은 테두리·경고 아이콘을 함께 사용한다.
- 탭이 다시 보이면 즉시 서버 시간을 재동기화해 계산하고, 연결이 끊겼으면 재접속 오버레이를 우선한다. 이전 `roundId`의 callback·응답·경고는 폐기한다.

[근거: 대표님 추가 결정 — 라운드 제한 시간, 공통 지침 §4.9·§5.4]

[근거: `PLANNING_PROMPT` UI/UX 원칙, 공통 지침 §4.1·§4.3~§4.5·§4.11]

## 6. 타이포그래피

- 제목, 방번호 확대, 정답·시간 종료 모달 제목, 큰 주요 버튼에는 `"Jua"`를 사용한다.
- 제시어, 추측 입력·피드, 참가자 이름, 작은 버튼과 본문에는 `"LINE Seed Sans KR"`를 사용한다.
- Jua는 장식성이 강하므로 20px 미만 본문, 입력값, 긴 문장, 카운트다운 숫자에 사용하지 않는다.
- 카운트다운은 LINE Seed Sans KR Bold와 `font-variant-numeric: tabular-nums`를 사용한다.
- 한글·영문·숫자가 섞인 제시어와 추측은 LINE Seed Sans KR 한 family로 렌더해 기준선과 자폭 변화를 줄인다.
- 폰트는 WOFF2로 자체 호스팅하고 `font-display: swap`을 사용한다. 로딩 실패 시 시스템 둥근 고딕 fallback으로 즉시 표시한다.

```css
--font-display: "Jua", "LINE Seed Sans KR", "Arial Rounded MT Bold",
  "Apple SD Gothic Neo", system-ui, sans-serif;
--font-body: "LINE Seed Sans KR", "Arial Rounded MT Bold",
  "Apple SD Gothic Neo", "Noto Sans KR", system-ui, sans-serif;
```

- 모바일 본문·입력 최솟값은 16px, 작은 보조 문구는 14px, 주요 버튼은 18px, 제목은 24px다.
- display font의 자간은 기본값을 유지하고 전부 대문자로 바꾸지 않는다.

[근거: 대표님 추가 결정 — 둥글고 귀여운 글씨체]

## 7. 접근성 합격 기준

- 모든 클릭 동작은 시맨틱 `button`, 링크는 `a`, 입력은 연결된 `label`을 사용한다.
- 포커스 표시를 제거하지 않으며 키보드만으로 로비, 추측, 진행자 제어, 모달을 조작할 수 있다.
- 색상 버튼은 색상 견본과 한국어 라벨을 함께 제공하고 `aria-pressed`를 사용한다.
- 펜 굵기는 `얇게`, `보통`, `굵게` 텍스트를 제공한다.
- 서버 상태, drawer 변경, 정답 확정, 재접속 결과는 `aria-live`로 알리되 스트로크와 모든 추측을 개별 음성 공지하지 않는다.
- 모달은 제목 연결, 포커스 트랩, Escape 정책, 닫은 뒤 원래 포커스 복귀를 구현한다.
- 상태는 색 외에 텍스트·아이콘·테두리 스타일로 구분한다.
- 일반 텍스트는 WCAG 2.1 AA 대비 4.5:1 이상, 큰 텍스트와 UI 경계는 3:1 이상이다.
- `prefers-reduced-motion: reduce`에서는 펄스, 이동, 글로우 애니메이션을 제거한다.
- 최소 터치 영역은 44×44 CSS px다.
- 폰트 다운로드 전후 레이아웃 이동이 버튼·입력 조작을 가리지 않아야 하며 fallback에서도 같은 최소 글자 크기를 유지한다.

[근거: 결정 D-13·D-19, 공통 지침 §4.9]

## 8. PWA 화면 동작

- manifest는 `name: "Doodle Guess"`, `short_name: "Doodle Guess"`, `display: "standalone"`, `orientation: "any"`를 사용한다.
- 앱 셸만 오프라인 캐시하며 WebSocket이 없을 때 게임이 가능한 것처럼 표시하지 않는다.
- 업데이트가 준비되어도 진행 중인 방을 자동 새로고침하지 않고 로비에서 적용한다.
- 최초 실행과 사용자가 실행한 새로고침은 로비에서 시작한다. 백그라운드 복귀 중 끊긴 연결만 탭 세션으로 자동 복구한다.
- 기존 `icon-192.png`, `icon-512.png`을 일반 아이콘으로 사용하고, 512 원본의 핵심 도안을 중앙 안전영역에 축소한 별도 maskable 아이콘을 사용한다.

[근거: 결정 D-01·D-18·D-19, 공통 지침 §4.11]
