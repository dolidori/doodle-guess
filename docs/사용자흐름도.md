# Doodle Guess 사용자흐름도

## 1. 공통 진입 흐름

```mermaid
flowchart TD
  A[앱 실행] --> B[로비]
  B --> C{서버 연결됨}
  C -- 아니오 --> D[연결 상태 표시와 생성·입장 비활성]
  D --> C
  C -- 예 --> E{사용자 행동}
  E -- 방 만들기 --> F[닉네임과 모드 입력]
  F --> G[서버 CREATE_ROOM 검증]
  E -- 방 입장 --> H[닉네임과 100~999 방번호 입력]
  H --> I[Enter 또는 입장하기]
  I --> J[서버 JOIN_ROOM 검증]
  G --> K[방 화면]
  J --> K
  G --> L[오류를 해당 폼에 표시]
  J --> L
```

- 일반 모드 생성자는 호스트 겸 초기 drawer다.
- 진행자 모드 생성자는 호스트 겸 진행자 겸 초기 drawer다.
- 방 정원은 연결 끊김 복구 슬롯을 포함해 30명이다.
- 최근 접속 항목은 입력값만 채우며 자동 입장하지 않는다.

[근거: 게임 설명 1~3행·10~12행, 결정 D-02~D-04]

## 2. 일반 모드 호스트 흐름

```mermaid
flowchart TD
  A[일반 모드 방 생성] --> B[호스트·drawer 권한 복원]
  B --> C{연결된 추측 자격자 1명 이상}
  C -- 아니오 --> D[시작 비활성·참여자 대기]
  D --> C
  C -- 예 --> E[20~180초 제한 시간을 5초 단위로 설정]
  E --> F[제시어 입력]
  F --> G[제시어 확정 및 시작]
  G --> H{서버 권한·입력·인원 검증}
  H -- 거부 --> F
  H -- 수락 --> I[PRIVATE 제시어 수신·서버 카운트다운 시작]
  I --> J[그리기와 공개 추측 피드 확인]
  J --> K{라운드 최종 상태}
  K -- 진행 --> J
  K -- 정답 확정 --> L[캔버스 잠금·정답자 모달 1회]
  K -- 시간 종료 --> M[캔버스 잠금·시간 종료 모달 1회]
  L --> N[해결 배너 유지]
  M --> O[시간 종료 배너 유지]
  N --> P[다음 라운드]
  O --> P
  P --> E
```

- 제시어 보기·가리기는 현재 탭의 로컬 상태다.
- 호스트는 자신이 제시어를 본 라운드에서 추측할 수 없다.
- `다음 라운드`에서 drawer 권한은 호스트에게 유지된다.

[근거: 게임 설명 4~7행, 결정 D-05~D-08·D-11]

## 3. 일반 추측자 흐름

```mermaid
flowchart TD
  A[방 입장] --> B[현재 그림·최근 추측·roundEndsAt 복원]
  B --> C{라운드 상태}
  C -- 제시어 준비 --> D[그리기 사용자 대기]
  C -- 진행 중 --> E[그림과 공개 추측 피드 확인]
  E --> F[추측 입력]
  F --> G[Enter 또는 제출]
  G --> H{서버 수락}
  H -- 형식·권한·Rate Limit 거부 --> I[입력 유지·인라인 오류]
  I --> F
  H -- 오답 수락 --> J[방 전체 공개 피드에 추가]
  J --> E
  H -- 정답 수락 --> K[정답 피드 항목과 ROUND_SOLVED]
  K --> L[입력 즉시 잠금]
  L --> M[정답자 모달 1회]
  M --> N[해결 배너와 다음 라운드 대기]
  E --> O{서버 시간 만료}
  O -- ROUND_EXPIRED --> P[입력 잠금·시간 종료 모달 1회]
  P --> Q[시간 종료 배너와 다음 라운드 대기]
```

- 서버에 먼저 수락된 정답 한 건만 정답이 된다.
- 비교는 모든 Unicode 공백만 제거하고 나머지 문자는 그대로 둔다.
- 서버가 수락하지 않은 문자열은 공개 피드에 나타나지 않는다.

[근거: 게임 설명 4행·9행, 결정 D-08~D-10]

## 4. 진행자 모드 흐름

```mermaid
flowchart TD
  A[진행자 모드 방 생성] --> B[호스트·진행자·drawer 권한]
  B --> C[20~180초 제한 시간을 5초 단위로 설정]
  C --> D{drawer 운영}
  D -- 직접 그리기 --> E[제시어 확정 및 시작]
  E --> T[서버 카운트다운 시작]
  T --> J
  D -- 권한 위임 --> F[연결 참여자 지정]
  F --> G[서버 ASSIGN_DRAWER 검증]
  G --> H[기존 확정 그림·제시어 유지]
  H --> I[새 drawer PRIVATE 제시어·도구 활성]
  I --> J{진행자 행동}
  J -- 계속 위임 --> K[공개 그림·추측·카운트다운 모니터링]
  J -- 권한 회수 --> L[서버 RECLAIM_DRAWER]
  L --> M[이전 drawer 미완성 스트로크 폐기]
  M --> N[진행자 drawer UI 활성]
  J -- 참여자 관리 --> O[내보내기 확인 후 KICK_PLAYER]
  K --> P{정답 또는 시간 종료}
  N --> P
  P -- 정답 --> Q[정답자 모달·입력 잠금]
  P -- 시간 종료 --> R[시간 종료 모달·입력 잠금]
  Q --> S[진행자가 다음 라운드]
  R --> S
  S --> C
```

- 진행자는 항상 PRIVATE 제시어 수신 자격이 있지만 화면에서는 기본 가림이다.
- 현재·과거 drawer와 진행자는 해당 라운드의 추측 자격이 없다.
- 위임과 회수 후에도 서버에 확정된 그림과 제시어는 유지된다.

[근거: 게임 설명 8행·13행, 결정 D-04·D-07·D-08·D-11·D-12]

## 5. 위임받은 drawer 흐름

```mermaid
flowchart TD
  A[PUBLIC_STATE에서 drawer 변경 확인] --> B[그리기 권한 토스트]
  B --> C{라운드 상태}
  C -- 준비 --> D[제시어 입력·확정 및 시작]
  C -- 진행 --> E[PRIVATE 제시어를 기본 가림으로 수신]
  D --> F[다색 펜·굵기·지우개·undo·clear 활성]
  E --> F
  F --> G[Pointer Events로 벡터 스트로크 전송]
  G --> H{권한 유지}
  H -- 예 --> F
  H -- 회수 --> I[미완성 로컬 스트로크 폐기]
  I --> J[도구 비활성·관람 화면]
  J --> K[라운드 종료까지 추측 비활성]
```

- 그리기 도구 상태는 로컬 UI 상태지만 색·굵기·tool 값은 서버 허용 목록에서만 고른다.
- `전체 지우기`는 확인 모달 뒤 서버가 수락했을 때만 캔버스를 비운다.

[근거: 게임 설명 6~8행, 결정 D-08·D-12·D-13]

## 6. 정답 경합과 모달 중복 방지 흐름

```mermaid
sequenceDiagram
  participant A as 추측자 A
  participant B as 추측자 B
  participant S as 서버 방 명령 큐
  participant C as 방 클라이언트
  A->>S: SUBMIT_GUESS
  B->>S: SUBMIT_GUESS
  S->>S: 도착 순서로 직렬 검증
  S-->>C: GUESS_SHARED eventSeq=51, guessSeq
  S->>S: round 상태를 SOLVED로 원자 변경
  S-->>C: ROUND_SOLVED eventSeq=51, eventId
  S->>S: 뒤 요청은 ROUND_ALREADY_SOLVED
  S-->>B: ERROR
  C->>C: allowedActions에서 SUBMIT_GUESS 제거
  C->>C: round-solved:{eventId} 키가 없을 때만 모달 큐 추가
```

- 정답 추측 순서는 `guessSeq`, 논리 이벤트 순서는 `eventSeq`, 결과 모달 중복은 `eventId`로 확정된다.
- 재접속 스냅샷이 이미 해결된 라운드를 포함해도 동일 모달 키를 재생하지 않는다.

[근거: `PLANNING_PROMPT` 핵심 불변식 5~6, 결정 D-10]

## 7. 라운드 제한 시간 흐름

```mermaid
flowchart TD
  A[제시어 준비] --> B{호스트 또는 진행자}
  B -- 예 --> C[20~180초 range slider]
  C --> D[5초 단위 변경·현재값 자연어 표시]
  D --> E[서버 SET_ROUND_DURATION 수락]
  B -- 아니오 --> F[설정값 읽기 전용]
  E --> G[drawer가 제시어 확정 및 시작]
  F --> G
  G --> H[서버 roundEndsAt 설정]
  H --> I[전 사용자 카운트다운 표시]
  I --> J{남은 시간 10초 이하}
  J -- 최초 1회 --> K[시각 경고·aria-live 경고]
  K --> L{서버 최종 이벤트}
  I --> L
  L -- ROUND_SOLVED --> M[정답 잠금·정답자 모달]
  L -- ROUND_EXPIRED --> N[그림·추측 잠금·시간 종료 모달]
  M --> O
  N --> O[호스트 또는 진행자의 다음 라운드 대기]
```

- 진행 중 slider는 disabled이며 변경 불가 사유를 표시한다.
- 새 방은 60초로 시작하고 다음 라운드는 마지막 서버 확정 설정값을 유지한다.
- 클라이언트 카운트다운은 표시용이며 0초 도달로 로컬 만료 이벤트를 만들지 않는다.
- 백그라운드 복귀와 재접속은 `/api/time` 왕복 측정으로 서버 시각을 다시 동기화하고 `roundEndsAt` 기준으로 즉시 복원한다. 이전 `roundId`의 지연 응답은 폐기한다.

[근거: 대표님 추가 결정 — 라운드 제한 시간]

## 8. 일반 참여자 재접속 흐름

```mermaid
flowchart TD
  A[WebSocket 끊김] --> B[RECONNECTING 차단 오버레이]
  B --> C{sessionStorage 복구 토큰 있음}
  C -- 예 --> D[토큰으로 JOIN_ROOM]
  C -- 아니오 --> E[방번호·원래 닉네임으로 JOIN_ROOM]
  D --> F{서버 복구 허용}
  E --> F
  F -- 예 --> G[기존 playerId·역할·열람 이력 복원]
  G --> H[PUBLIC·PRIVATE·그림·추측·allowedActions 스냅샷]
  H --> I[eventSeq·drawingSeq·guessSeq·roundEndsAt 확인]
  I --> J[오버레이 닫기·재연결 토스트]
  F -- 강퇴·중복 연결·방 없음 --> K[오류별 종료 화면]
  K --> L[로비로 이동]
```

- 다른 닉네임으로 입장하면 기존 슬롯 복구가 아니라 새 플레이어로 처리한다.
- 같은 기기의 다른 탭은 별도 `sessionStorage` 토큰을 사용해 독립 플레이어가 된다.
- drawer로 복귀하면 제시어는 다시 가려진 상태에서 시작한다.

[근거: 게임 설명 13행, 결정 D-14~D-16, 공통 지침 §2.3·§5.4]

## 9. 호스트 연결 끊김과 30분 종료 흐름

```mermaid
flowchart TD
  A[호스트 연결 끊김] --> B[isHost와 hostId 유지·connected=false]
  B --> C[모든 사용자에게 30분 종료 시각 브로드캐스트]
  C --> D[호스트 부재 배너와 서버 기준 카운트다운]
  D --> E{30분 안에 복귀}
  E -- 토큰 복구 --> F[같은 호스트 슬롯 복원]
  E -- 정확히 같은 닉네임 폴백 --> F
  F --> G[호스트 권한 유지·배너 제거]
  E -- 복귀하지 않음 --> H[방 종료 이벤트]
  H --> I[종료 사유 차단 오버레이]
  I --> J[로비 이동·방 상태 폐기]
```

- 호스트 권한은 어떤 사용자에게도 자동 이양하지 않는다.
- 이미 연결된 호스트 닉네임을 다른 연결이 사용하려 하면 거부한다.
- 호스트 부재 중에도 서버가 내려준 `allowedActions`에 포함된 현재 라운드 액션은 계속할 수 있다.

[근거: 게임 설명 14행, 결정 D-16·D-17]

## 10. 강퇴 흐름

```mermaid
flowchart TD
  A[호스트 또는 진행자가 내보내기] --> B[대상·결과 확인 모달]
  B --> C[KICK_PLAYER]
  C --> D{서버 권한·대상 검증}
  D -- 거부 --> E[관리자에게 오류 토스트]
  D -- 수락 --> F[대상 연결과 슬롯 제거]
  F --> G[방 생존 기간 ban 기록]
  G --> H[대상에게 강퇴 차단 화면]
  H --> I[로컬 방·PRIVATE 상태 폐기]
  I --> J[로비 이동]
```

- 같은 복구 토큰과 닉네임의 재입장은 방이 닫힐 때까지 거부한다.
- 새 탭과 새 닉네임 우회까지 계정 없이 완전히 막을 수 없다는 운영 한계를 도움말에 명시한다.

[근거: 게임 설명 13행, 결정 D-14]

## 11. PWA 및 백그라운드 복귀 흐름

```mermaid
flowchart TD
  A[앱이 백그라운드로 이동] --> B[현재 탭 세션 유지]
  B --> C[포그라운드 복귀]
  C --> D{WebSocket 정상}
  D -- 예 --> E[현재 화면 계속]
  D -- 아니오 --> F[중복 없는 재연결 1회 시작]
  F --> G[일반 재접속 흐름]
  H[사용자 새로고침 또는 새 실행] --> I[로비 시작]
  J[서비스워커 업데이트 준비] --> K{현재 방 안}
  K -- 예 --> L[로비 복귀 후 적용 예약]
  K -- 아니오 --> M[업데이트 적용]
```

- 앱 셸 캐시가 있어도 서버 연결이 없으면 방 생성·입장·게임 조작을 비활성화한다.
- 서버 재시작 뒤 사라진 방은 복구하지 않고 종료 사유를 표시한다.

[근거: 결정 D-18·D-19, 공통 지침 §4.11·§5.4]
