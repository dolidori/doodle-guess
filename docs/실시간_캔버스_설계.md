# Doodle Guess 실시간 캔버스 설계

## 1. 문서 목적과 근거

이 문서는 구현 단계의 벡터 캔버스 단일 기준이다. 통신 필드의 최종 계약은 `WebSocket_이벤트_명세.md`, 상태 필드의 최종 계약은 `게임_상태_설계.json`을 따른다.

- 벡터 방식: `게임 설명.md` 6행
- 현재 그리기 권한자만 입력: `게임 설명.md` 5행, 8행
- 권한 변경 시 그림·제시어 유지: `결정_기록.md` D-12
- 다색 펜·3굵기·지우개·undo·clear: `결정_기록.md` D-13
- 서버 권위 라운드 제한 시간: `결정_기록.md` D-21
- 서버 권위 및 입력 검증: 공통 지침 §1.2, §3.7
- 수치 제한·배치·백프레셔는 게임 설명에 없어 결정한 구현 규칙이다.

## 2. 권위 모델

서버의 `DrawingState`가 유일한 권위 데이터다. 클라이언트는 포인터 이동을 즉시 임시 레이어에 그려 입력 지연을 숨길 수 있지만, 이 레이어는 서버가 같은 `strokeId`와 `batchSeq`를 되보낸 뒤에만 확정 레이어로 승격한다.

캔버스 전체 비트맵은 입력 동기화에 사용하지 않는다. 새 입장·재접속·느린 연결 복구에는 벡터 스냅샷을 사용한다. 썸네일을 추후 만들더라도 표시용 파생물일 뿐 권위 데이터가 아니다.

한 방에는 `drawerId`가 최대 하나만 존재한다. 서버는 배치를 처리하는 순간 연결 컨텍스트의 사용자, `roundId`, `drawingRevision`, `drawerEpoch`, `roundEndsAt`을 모두 다시 검증한다. 클라이언트가 보낸 `authorId`는 받지 않는다.

## 3. 좌표와 렌더링

- 좌표는 캔버스 콘텐츠 영역의 좌상단을 `(0, 0)`, 우하단을 `(1, 1)`로 한 정규화 좌표다.
- 서버는 `Number.isFinite(x/y)`와 `0 <= x/y <= 1`을 검사한다. 범위 밖 값은 보정하지 않고 요청 전체를 거부한다.
- 전송 좌표는 소수점 넷째 자리로 반올림한다. 서버는 받은 값을 그대로 권위 벡터에 저장한다.
- 굵기는 캔버스의 짧은 변에 대한 비율이다. 화면 크기가 달라도 동일한 상대 굵기로 렌더링한다.
- 점 사이 연결은 round line cap, round line join을 사용하는 2D Canvas 경로다.
- Pointer Events를 사용하고 캔버스에 `touch-action: none`과 pointer capture를 적용한다. 마우스·터치·펜을 같은 코드 경로로 처리한다.

## 4. 고정 도구

### 4.1 접근성 팔레트

자유 색상 입력은 허용하지 않는다. 서버와 클라이언트가 아래 enum과 HEX를 함께 고정한다. UI는 색상 견본과 텍스트 라벨을 함께 표시한다.

| enum | 라벨 | HEX |
|---|---|---|
| `BLACK` | 검정 | `#111827` |
| `BLUE` | 파랑 | `#0072B2` |
| `ORANGE` | 주황 | `#E69F00` |
| `GREEN` | 초록 | `#009E73` |
| `VERMILION` | 다홍 | `#D55E00` |
| `PURPLE` | 보라 | `#7B2CBF` |

### 4.2 굵기

| enum | 정규화 너비 |
|---|---:|
| `THIN` | `0.003` |
| `MEDIUM` | `0.007` |
| `THICK` | `0.014` |

펜과 지우개가 같은 3단계 정규화 너비를 사용한다. 지우개도 벡터 스트로크다. 렌더러는 `ERASER` 스트로크를 `destination-out` 합성으로 순서대로 적용한다. 따라서 지우개 사용에도 비트맵 전송이 필요하지 않으며 undo로 마지막 지우개 스트로크를 되돌릴 수 있다.

## 5. 스트로크와 배치

권위 스트로크는 다음 의미를 갖는다.

```ts
type Stroke = {
  strokeId: string;              // UUID, 한 라운드에서 유일
  authorId: string;              // 서버가 연결 컨텍스트에서 설정
  tool: 'PEN' | 'ERASER';
  color: PaletteColor | null;    // PEN은 팔레트, ERASER는 null
  width: 'THIN' | 'MEDIUM' | 'THICK';
  points: Array<{ x: number; y: number }>;
  finalized: boolean;
  undone: boolean;
  lastBatchSeq: number;
};
```

`DRAW_STROKE_BATCH`는 다음 필드를 보낸다.

```ts
type StrokeBatchRequest = {
  roundId: string;
  drawingRevision: number;
  drawerEpoch: number;
  strokeId: string;
  batchSeq: number;              // 첫 배치는 0, 이후 1씩 증가
  isFinal: boolean;
  tool: 'PEN' | 'ERASER';
  color: PaletteColor | null;
  width: 'THIN' | 'MEDIUM' | 'THICK';
  points: Array<{ x: number; y: number }>;
};
```

- 모든 배치는 `tool`, `color`, `width`가 필수이며 같은 stroke 안에서 첫 배치와 정확히 같아야 한다.
- `PEN`은 팔레트 color가 필수이고 `ERASER`는 `color:null`만 허용한다. 이 조건은 서버 저장, 실시간 delta, snapshot에도 동일하다.
- 배치당 점은 1~64개, JSON 메시지는 UTF-8 기준 8KiB 이하다.
- 스트로크당 점은 최대 2,048개다.
- 한 revision의 상한은 스트로크 1,000개, 점 50,000개, 직렬화된 벡터 4MiB 중 먼저 도달한 값이다.
- 브라우저는 원시 포인터를 로컬 미리보기에 사용하되 네트워크 점은 최대 초당 60개로 재표본화하고 50ms마다 배치한다. pointerup·pointercancel 때 남은 점을 `isFinal:true`로 즉시 보낸다.
- 점 하나로 끝난 스트로크는 굵기 지름의 원으로 렌더링한다.

## 6. 순서, 중복, 누락

식별 키는 `roundId:drawingRevision:strokeId:batchSeq`다.

- 서버가 기대하는 다음 `batchSeq`와 같으면 수락하고 `drawingSeq`를 1 증가시킨 뒤 방 전체에 되보낸다.
- 이미 수락한 `batchSeq` 재전송은 상태를 바꾸지 않는다. 서버는 기존 수락 결과를 발신자에게 다시 보내 멱등성을 보장한다.
- 기대값보다 큰 배치는 `STROKE_SEQUENCE_GAP`으로 거부하고 해당 연결에 최신 벡터 스냅샷을 자동 전송한다.
- WebSocket 연결 내부 순서는 보장되지만 재접속과 애플리케이션 재시도 때문에 위 중복 규칙을 유지한다.

`drawingRevision`은 새 라운드 준비와 전체 지우기 때 증가한다. `drawingSeq`는 revision 안에서 0부터 시작해 수락된 batch와 undo마다 증가한다. `drawerEpoch`은 권한 지정·회수 때 증가한다. 이 세 값을 함께 사용하면 이전 라운드, clear 이전, 이전 그리기 권한자의 지연 패킷이 현재 그림에 섞이지 않는다.

## 7. 권한 변경과 연결 종료

D-12에 따라 권한 변경은 기존 제시어와 확정 그림을 유지한다.

1. 방 큐에서 `drawerEpoch`을 증가시키고 `drawerId`를 바꾼다.
2. 이전 drawer의 서버 수락분은 짧은 확정 스트로크로 남긴다.
3. 이전 drawer의 미전송 로컬 점과 아직 서버가 수락하지 않은 배치는 폐기한다.
4. 새 drawer는 새 epoch과 새 `strokeId`로 시작한다.
5. 제시어를 본 이전 drawer는 해당 라운드의 `keywordExposedPlayerIds`에 남아 추측할 수 없다.

연결이 끊긴 drawer의 권한은 자동으로 다른 사람에게 넘어가지 않는다. 일반 모드 호스트의 연결이 끊기면 `drawerId`와 `isHost`를 유지하고 입력만 중단된다. 진행자 모드에서는 연결된 진행자가 명시적으로 `ASSIGN_DRAWER` 또는 `RECLAIM_DRAWER`를 실행해야 한다.

서버 시각이 `roundEndsAt` 이상이면 expiry timer callback의 실행 여부와 관계없이 새 batch·undo·clear를 거부한다. `ROUND_EXPIRED` 내부 명령이 방 큐에서 실행되면 그림과 추측을 함께 잠근다. 이미 서버가 수락한 벡터는 남기고, 클라이언트의 미전송 preview와 진행 중 입력은 폐기한다.

## 8. Undo와 전체 지우기

`UNDO_LAST_STROKE`는 현재 revision에서 undo되지 않은 마지막 확정 스트로크 하나를 `undone=true`로 표시해 활성 합성에서 제거한다. 작성자가 이전 drawer여도 화면상 마지막 스트로크이면 대상이 된다. 현재 drawer만 요청할 수 있다.

- 성공 시 `drawingSeq` 증가, 서버는 `STROKE_UNDONE`을 방 전체에 보낸다.
- 대상이 없으면 `NO_STROKE_TO_UNDO`.
- 아직 진행 중인 스트로크가 있으면 먼저 서버 수락분을 확정한 뒤 마지막 스트로크로 취급한다.

`CLEAR_DRAWING`은 현재 drawer만 요청할 수 있다.

- 기존 벡터를 비우고 `drawingRevision` 증가, `drawingSeq=0`으로 설정한다.
- 라운드와 제시어는 유지한다.
- 서버는 새 revision을 담은 `DRAWING_CLEARED`를 방 전체에 보낸다.
- clear 이전 revision의 지연 배치는 `STALE_DRAWING_REVISION`으로 거부한다.

undo와 clear는 방 큐의 일반 명령이므로 권한 지정·정답·강퇴와 동일한 FIFO 순서로 원자 처리된다.

## 9. 스냅샷과 재접속

서버는 방 큐 안에서 다음 메타데이터를 고정한 뒤 스냅샷을 만든다.

```ts
type DrawingSnapshotMeta = {
  snapshotId: string;
  roundId: string;
  drawingRevision: number;
  lastDrawingSeq: number;
  totalChunks: number;
  sha256: string;
};
```

- 각 `DRAWING_SNAPSHOT` 청크의 JSON payload는 최대 64KiB다.
- 스냅샷에는 `undone=false`인 활성 스트로크만 원래 합성 순서대로 포함한다.
- 큰 스트로크는 `strokeId`, `fragmentIndex`, `fragmentCount`가 있는 fragment로 나눈다.
- SHA-256은 재조립한 정규 벡터 JSON에 대해 계산한다.
- 클라이언트는 스냅샷 조립 중 `lastDrawingSeq`보다 큰 실시간 delta를 임시 버퍼에 저장하고, 해시 검증 후 순서대로 적용한다.
- chunk 누락·해시 불일치는 클라이언트가 현재 소켓을 닫고 자동 재접속해 새 스냅샷을 받는 방식으로 복구한다. 별도 resync 요청 이벤트는 두지 않는다. 재접속 뒤에도 다시 실패하면 연결 오류 오버레이를 유지한다.
- 재접속 순서는 `ROOM_SESSION` → `PUBLIC_STATE` → `PRIVATE_STATE` → `DRAWING_SNAPSHOT`이며, 그 뒤 실시간 delta를 적용한다.

최근 공개 추측은 그림 스냅샷에 섞지 않고 `PUBLIC_STATE.guessFeed`로 복원한다.

## 10. 백프레셔

서버는 연결별 `bufferedAmount`를 감시한다.

| 상태 | 기준 | 처리 |
|---|---:|---|
| 정상 | `< 256KiB` | 실시간 delta 전송 |
| 느림 | `>= 256KiB` | 해당 연결의 stroke delta 전송 중지, snapshot-required 표시 |
| 회복 | `< 128KiB` | 최신 snapshot을 64KiB 청크로 전송; 각 청크 전송 전 256KiB 미만 확인 |
| 실패 | `>= 1MiB`가 5초 지속 | 1013 종료, 자동 재접속 |

느린 연결을 위해 방 전체 브로드캐스트를 기다리지 않는다. 연결마다 독립적으로 skip/snapshot 처리한다. 발신 drawer의 `bufferedAmount`가 256KiB 이상이면 클라이언트는 네트워크 표본화를 초당 30점으로 낮추고 새 배치를 무한 적재하지 않는다. 1MiB가 되면 현재 로컬 미확정 스트로크를 폐기하고 재연결한다.

## 11. 검증 기준

1. 같은 벡터를 320×568, 768×1024, 1920×1080 콘텐츠 영역에 렌더링했을 때 정규화 기하 오차가 1 CSS px 이하다.
2. 권한 변경 직후 이전 epoch의 1,000개 지연 배치를 보내도 수락 건수는 0이다.
3. duplicate batch는 점을 중복 추가하지 않고 gap은 자동 스냅샷으로 수렴한다.
4. 펜 6색·각 3굵기와 지우개 3굵기가 snapshot 후 픽셀 비교 허용 오차 1% 이내로 재현된다.
5. undo는 펜과 지우개를 포함한 마지막 확정 스트로크 하나만 제거한다.
6. clear와 지연 batch 경합에서 이전 revision의 점이 새 그림에 0개 포함된다.
7. NaN, Infinity, 범위 밖 좌표, 65점 batch, 8KiB 초과, 2,049점 stroke를 모두 거부한다.
8. 느린 관찰자 한 명이 있어도 나머지 연결의 stroke 지연 p95가 150ms 이하다.
9. 재접속 snapshot 적용 중 새 delta가 도착해도 최종 stroke 순서·점 수·해시가 서버와 같다.
10. `roundEndsAt` 이후 batch·undo·clear 수락은 timer callback 지연 여부와 무관하게 0건이다.
