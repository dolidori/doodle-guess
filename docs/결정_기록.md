## 확정 결정

아래 항목은 모두 **게임 설명에 없어 결정한 부분**이며 2026-07-23 대표님 확인으로 확정되었다.

### D-01 최종 게임명

- 대표님 결정: 영문 표기 `Doodle Guess`, 한글 보조 표기 `두들 게스`
- 대안: 완전한 한글 이름 또는 새 브랜드명
- 영향: PWA manifest, 브라우저 제목, 로비·헤더, 접근성 라벨, 문서명

### D-02 3자리 방번호 범위

- 대표님 결정: `100~999`
- 대안: 선행 0을 허용하는 `000~999`
- 영향: 생성 가능한 동시 방 수(900/1,000), 입력·표시·테스트 경계값

### D-03 방 정원

- 대표님 결정: 논리 플레이어 슬롯 최대 30명이며 호스트와 진행자를 포함한다. 재접속 유예 중인 슬롯도 정원에 포함한다.
- 대안: 진행자를 제외하거나, 호스트 외 참여자 30명으로 정의한다.
- 영향: 마지막 자리 입장 경합, 플레이어 목록 UI, 팬아웃·부하 목표

### D-04 모드 개설·전환

- 대표님 결정: 방 생성 시 `일반 모드` 또는 `진행자 모드`를 고르고 방 수명 동안 전환하지 않는다. 일반 모드 생성자는 호스트 겸 초기 그리기 권한자다. 진행자 모드 생성자는 호스트 겸 진행자이며 초기 그리기 권한을 가진다.
- 대안: 대기 상태에서만 모드 전환을 허용한다.
- 영향: 역할 조합, 생성 이벤트, 권한 표, 전환 경합과 UI 복잡도

### D-05 최소 입장 인원과 시작 조건

- 대표님 결정: 연결된 그리기 권한자 1명과 정답 제출 자격이 있는 연결 참여자 1명 이상일 때 시작할 수 있다.
- 대안: 혼자 연습을 허용하거나 최소 인원을 3명 이상으로 둔다.
- 영향: `START_ROUND` 검증, 버튼 활성화, 연결 끊김 시 교착 처리

### D-06 제시어 확정과 라운드 시작

- 대표님 결정: `제시어 확정 및 시작` 한 동작으로 제시어 저장과 라운드 시작을 원자 처리하며 별도 시작 버튼을 추가하지 않는다.
- 대안: 제시어 저장 뒤 호스트/진행자가 별도 시작 버튼을 누른다.
- 영향: 라운드 상태 수, 이벤트 수, 중복 클릭·권한 검증

### D-07 정답 후 다음 라운드

- 대표님 결정: 일반 모드는 호스트, 진행자 모드는 진행자가 `다음 라운드`를 실행한다. 기존 그리기 권한자는 유지되며 새 제시어를 확정하면 시작한다.
- 대안: 현재 그리기 권한자가 직접 다음 라운드를 열거나 정답 직후 자동 전환한다.
- 영향: `ROUND_SOLVED` 이후 허용 액션, 캔버스 초기화 시점, 진행 권한

### D-08 추측 입력 자격

- 대표님 결정: 현재·과거 그리기 권한으로 해당 라운드 제시어를 본 사람과 진행자는 추측할 수 없다. 그 밖의 연결 참여자만 추측할 수 있다.
- 대안: 문구 그대로 모든 접속자에게 입력을 허용하되, 제시어 열람자는 정답자에서 제외한다.
- 영향: 공정성, `allowedActions`, 정답자 검증, 권한 변경 이력

### D-09 정답 문자열 정규화

- 대표님 결정: 모든 Unicode 공백 문자만 제거하고 나머지는 그대로 비교한다.
- 대안: 영문 대소문자 무시, 문장부호 제거, Unicode NFC/NFKC를 추가한다.
- 영향: 정답 판정 함수와 테스트 벡터, 예상치 못한 오답/정답 범위

### D-10 추측 입력 공개 범위

- 대표님 결정: 서버가 정상 수락한 모든 추측 입력을 제출자 닉네임·순번과 함께 해당 방 참여자 전원에게 실시간 공유한다. 정답 입력은 정답 확정 이벤트와 함께 공개한다.
- 적용 경계: 제시어 입력과 정규화 값은 계속 PRIVATE/서버 전용이다. 권한 없는 요청, Rate Limit 초과, 스키마 검증 실패처럼 서버가 수락하지 않은 데이터는 공유하지 않는다.
- 영향: 공개 추측 피드, 방별 `GUESS_SHARED` 이벤트, 텍스트 길이·Rate Limit·악용 방지, 재접속 시 최근 추측 복원

### D-11 제시어 가리기 상태

- 대표님 결정: 권한자 각 화면의 로컬 표시 상태다. 서버는 권한자에게 PRIVATE 제시어를 보내되 일반 참여자에게는 전송하지 않는다.
- 대안: 서버에 권한자별 가림 상태를 저장·복원한다.
- 영향: 이벤트 필요 여부, 재접속 복원, PRIVATE 정보 경계

### D-12 그리기 권한 변경 시 라운드 데이터

- 대표님 결정: 기존 그림과 제시어를 유지한다. 제시어를 본 이전 그리기 사용자는 해당 라운드가 끝날 때까지 추측 자격을 얻지 않는다. 미완성 로컬 스트로크는 폐기한다.
- 대안: 권한 변경 시 그림과 제시어를 모두 초기화하고 새 라운드를 준비한다.
- 영향: 연속성, 공정성, PRIVATE 수신자 변경, 스트로크 종료 규칙

### D-13 최소 그림 도구

- 대표님 결정: 다색 펜, 3단계 굵기, 지우개, 마지막 스트로크 되돌리기, 전체 지우기를 제공한다.
- 적용안: 자유 색상 선택기 대신 캔버스 대비와 색각 접근성을 고려한 고정 팔레트를 사용하고 각 색상에 텍스트 라벨을 제공한다.
- 영향: Stroke의 `color` 검증, 캔버스 이벤트, 모바일 툴바, 되돌리기·초기화 경합

### D-14 강퇴와 재입장

- 대표님 결정: 강퇴 시 연결과 슬롯을 제거하고 방이 닫힐 때까지 같은 복구 토큰과 같은 닉네임의 재입장을 막는다. 계정이 없으므로 새 탭·새 닉네임 우회까지 확실히 차단할 수 없다는 한계를 명시한다.
- 대안: 현재 연결만 종료하고 즉시 재입장을 허용하거나, IP 기반 임시 차단을 추가한다.
- 영향: ban 목록, 개인정보·오탐 위험, 강퇴 실효성, 재입장 오류 코드

### D-15 다른 닉네임 재입장

- 대표님 결정: 다른 닉네임은 새 플레이어 슬롯으로 입장한다. 기존 연결 끊김 슬롯은 복구 토큰 또는 원래 닉네임으로만 복원한다.
- 대안: 사용자가 기존 복구 토큰을 제시하면 같은 슬롯의 닉네임을 변경한다.
- 영향: 정원 계산, 역할·그리기 열람 이력, 이벤트 로그의 동일인 추적

### D-16 호스트 복구 인증

- 대표님 결정: 탭별 `sessionStorage` 복구 토큰을 우선 사용하고, 토큰이 사라진 경우 원래 호스트가 연결 끊김 상태일 때 정확히 같은 닉네임으로 복구하는 폴백을 둔다. 이미 연결된 호스트 닉네임 탈취는 거부한다.
- 대안: 원문 그대로 닉네임만 사용하거나 별도 PIN을 필수화한다.
- 영향: 사칭 위험, 원문 호환성, 다중 탭 경합, `JOIN_ROOM` 계약

### D-17 호스트 장기 부재와 방 종료

- 대표님 결정: 호스트 연결이 끊겨도 자동 이양하지 않고 30분간 방을 유지한다. 그 안에 복귀하지 않으면 연결된 참여자에게 종료 사유를 알리고 방을 닫는다.
- 대안: 다른 참여자가 있는 동안 무기한 유지하거나, 모든 연결이 사라진 시점부터 별도 유예 시간을 둔다.
- 영향: 메모리 정리, 호스트 부재 중 허용 액션, 종료 타이머와 재접속 UX

### D-18 서버 재시작 복구

- 대표님 결정: 일회성 인메모리 세션으로 운영하며 서버 재시작 시 방은 복구하지 않는다.
- 대안: DB 스냅샷으로 방·라운드·그림을 복구한다.
- 영향: 기술 스택, 배포, 상태 직렬화, 개인정보 보존, 개발 규모

### D-19 시각 방향

- 대표님 결정: 기존 아이콘의 보라·인디고 배경, 노랑 강조, 흰 스케치북 표면을 이어가는 밝은 캔버스 중심 테마를 사용한다. 상태는 색뿐 아니라 텍스트·아이콘·선 스타일로도 구분한다.
- 대안: 공통 지침의 다크·골드 테마 또는 흑백 스케치북 테마
- 영향: 디자인 토큰, PWA theme/background 색, 대비·접근성, maskable 아이콘 처리

### D-20 글씨체

- 대표님 결정: 게임의 밝고 귀여운 분위기에 맞는 둥근 한글 글씨체를 사용한다.
- 적용안: 제목·큰 버튼은 `Jua`, 제시어·추측 입력·작은 본문은 `LINE Seed Sans KR`을 자체 호스팅한다. 외부 폰트 로딩 실패에 대비한 시스템 둥근 고딕 fallback과 `font-display: swap`을 적용하고 OFL 라이선스 파일과 출처를 함께 보관한다.
- 영향: 디자인 토큰, PWA 초기 로딩, 한글·영문·숫자 폭, 모바일 입력 가독성

### D-21 라운드 제한 시간

- 대표님 결정: 방장 또는 진행자가 그리기 제한 시간을 정한다.
- 적용안: 라운드 시작 전에 20~180초 슬라이더에서 5초 단위로 선택하며 기본값은 60초다. 진행 중에는 변경할 수 없다. 제시어 확정과 동시에 서버 기준 타이머가 시작되고 만료 시 라운드는 `ROUND_EXPIRED`가 되어 그림과 추측을 모두 잠근다. 일반 모드는 호스트, 진행자 모드는 진행자가 다음 라운드를 준비한다.
- 영향: Room 설정, `roundEndsAt`, 서버 타이머, `SET_ROUND_DURATION`·`ROUND_EXPIRED`, 카운트다운·재접속 복원·경합 테스트

### D-22 정답 판정 모드와 점수

- 대표님 결정: 대기실에서 `타이머까지 계속(UNTIL_TIMER)`와 `선착순 종료(FIRST_CORRECT)` 중 하나를 선택한다. 기본값은 타이머까지 계속이다.
- 선착순 종료: 최초 정답 즉시 라운드를 잠근다.
- 타이머까지 계속: 정답 내용을 공개 피드에서 가리고, 맞힌 사용자의 추가 추측만 막은 채 제한 시간까지 진행한다. 현재 연결된 정답 입력 가능 참여자가 모두 맞히면 제한 시간 전이라도 즉시 라운드를 종료한다.
- 점수: 정답자는 각각 1점, 해당 라운드의 그림 담당자는 정답자가 한 명 이상 나오면 최대 1점만 받는다. 점수는 방이 유지되는 동안 누적되고 라운드·정답 모드 변경으로 초기화하지 않는다.
- 영향: `answerMode`, Player `score`, `correctPlayerIds`, 정답 피드 가림, 대기실 UI와 재접속 상태

### D-23 대기실 복귀와 그림 담당자 지정

- 대표님 결정: 호스트 또는 진행자는 진행 중이거나 끝난 라운드에서 방 전체를 대기실로 되돌릴 수 있다. 참가자와 누적 점수는 유지한다.
- 대기실에서는 일반 모드 호스트와 진행자가 다음 그림 담당자를 지정하거나 자신에게 회수할 수 있다. 활성 라운드 중 담당자 교체는 기존처럼 진행자 모드에서만 허용한다.
- 영향: `RETURN_TO_WAITING`, 대기실 `ASSIGN_DRAWER`·`RECLAIM_DRAWER`, 라운드 초기화와 점수 보존

### D-24 배경음

- 대표님 결정: `bgm1.mp3`~`bgm5.mp3` 중 첫 곡과 다음 곡을 무작위로 선택해 무한 재생하되 같은 곡을 연속 재생하지 않는다.

### D-26 제시어 다시 뽑기

- 대표님 결정: 서버가 기본 제시어 목록에서 추천 제시어를 뽑아 주고, 그리기 담당자가 마음에 들지 않으면 다시 뽑을 수 있다.
- **한 사람당** 라운드당 최대 5회(`MAX_KEYWORD_SHUFFLES`)다. 소진하면 액션 자체가 `allowedActions`에서 빠진다. 라운드가 바뀌면 다시 찬다.
- 횟수는 라운드 공용이 아니라 playerId별로 센다. 공용으로 두면 방장이 쓴 1회가 넘겨받은 사람 몫에서도 깎인다.
- 직전 추천 제시어는 후보에서 빼 같은 값이 연속으로 나오지 않게 한다.
- 영향: `SHUFFLE_KEYWORD`, `suggestedKeyword`·`lastSuggestedKeyword`·`shuffleCount`, `remainingKeywordShuffles`, `SHUFFLE_LIMIT`

### D-27 제시어 기본 가림과 열람 신고 (D-11 개정)

- 문제: 방을 만들면 방장이 자동으로 그리기 담당자가 되어 추천 제시어가 화면에 그대로 보였다. 방장이 다른 사람에게 그리기를 넘겨도 이미 답을 알아 추측이 무의미해졌다.
- 대표님 결정: 제시어는 기본적으로 가려 두고 실제로 그리는 사람만 본다. 방장도 게임에 참여할 수 있어야 한다.
- 적용안: 준비 단계 추천 제시어는 `••••••`로 가린 채 시작하고 「보기」를 눌러야 드러난다. 글자 수도 숨기도록 마스킹 길이를 고정한다.
- 「보기」를 누르면 `REVEAL_KEYWORD`로 서버에 열람을 신고한다. 서버가 「봤는지」를 알아야 인계 시점에 판단할 수 있다.
- **제시어를 본 사람이 그리기 권한을 넘기면** 추천 제시어를 새로 뽑고 **넘기는 사람 몫**의 다시 뽑기 횟수를 1회 소모한다. 넘겨받는 사람 횟수는 건드리지 않는다. 보지 않고 넘기면 제시어도 횟수도 그대로다. 지정과 회수 양쪽에 대칭으로 적용한다.
- 확정된 라운드 제시어의 보기/가리기는 D-11 그대로 화면 로컬 상태다. 서버는 관여하지 않는다.
- 영향: `REVEAL_KEYWORD`, `suggestedKeywordSeenBy`, `ASSIGN_DRAWER`·`RECLAIM_DRAWER` 재추첨, `KeywordPanel` 기본 가림

### D-28 제시어 잠금 (진행자 전용)

- 대표님 결정: 진행자가 제시어를 정해 주고 참가자가 바꾸지 못하게 하는 기능을 둔다.
- 적용안: 「다시 뽑기」 옆에 「잠금」 버튼을 둔다. 잠그면 그리기 담당자는 제시어를 바꿀 수도 다시 뽑을 수도 없고, 제시어를 보고 시작 버튼만 누른다.
- **진행자 모드의 진행자에게만** 준다. 일반 모드 방장은 제시어에 관여하지 않고 그리기 권한만 넘긴다. 진행자는 원래 추측에 참여하지 않으므로 답을 알아도 공정성 문제가 없다.
- 진행자는 내용을 보지 않은 채로도 잠글 수 있다. 가려진 값을 그대로 확정한다.
- 잠긴 제시어는 조작된 `SET_KEYWORD_AND_START` payload로도 바뀌지 않는다. 서버가 payload를 무시하고 잠긴 값으로 시작한다.
- 잠금은 라운드가 시작될 때 소비되고 라운드가 바뀌면 해제된다.
- 영향: `LOCK_KEYWORD`·`UNLOCK_KEYWORD`, `lockedKeyword`, `keywordLocked`, `KEYWORD_LOCKED`

### D-29 라운드 종료 화면에서 담당자 교체와 `START_NEXT_ROUND` 제거

- 문제: 담당자 교체가 준비 단계에서만 가능해, 라운드가 끝난 뒤 다음 사람에게 넘기려면 「대기실로 돌아가기」를 먼저 눌러야 했다.
- 대표님 결정: 대기실을 거치지 않고 라운드 종료 화면에서 바로 넘길 수 있게 한다.
- 적용안: 담당자 지정·회수 허용 구간을 「라운드 사이」(`PREPARING_KEYWORD`, 그리고 `RESULTS`가 아닌 `SOLVED`/`EXPIRED`)로 넓힌다. 시상식 중에는 막는다.
- 이때 `keywordExposedPlayerIds`에는 **라운드 진행 중**에 인계받은 담당자만 넣는다. 끝난 라운드의 정답은 이미 공개되어 지킬 대상이 아니고, 넣으면 다음 라운드 시작 조건이 잘못 막힌다.
- `START_NEXT_ROUND`는 제거한다. `RETURN_TO_WAITING`과 효과가 완전히 같고(둘 다 새 라운드를 준비 상태로 연다) 조건만 좁았다. 클라이언트가 쓰지 않던 죽은 경로였다.
- 영향: `allowedActions` 17개로 축소, C→S 20개, `permissionService` 담당자 관리 조건, `tests/load/scenario.js`

### D-30 D-22 점수 산식 정정

- D-22의 「정답자 각각 1점, 그림 담당자 최대 1점」은 구현과 다르다. 실제 산식이 정본이다.

### D-31 펜을 뗀 획의 미리보기 인계

- 증상: 획을 그리고 펜을 떼면 그 획이 처음부터 다시 그려지는 것처럼 보였다.
- 원인: `finish()`가 펜을 떼는 즉시 미리보기 레이어를 지웠다. 본 캔버스는 서버가 되돌려준 `STROKE_BATCH`만 그리는데, 배치는 120ms마다 나눠 보내므로 아직 왕복이 끝나지 않은 뒷부분이 사라졌다가 배치 단위로 다시 채워졌다. 지연이 클수록 남아 있는 앞부분이 짧아 「처음부터 다시 그려지는」 것처럼 보인다.
- 적용안: 펜을 뗀 획을 `settlingRef`에 옮겨 미리보기에 계속 그린다. 서버 확정본(`finalized`)이 도착하거나, 되돌리기(`undone`)·전체 지우기·라운드 교체로 `drawingRevision`이 바뀌면 그때 비운다. 새 획을 시작할 때와 그리기 권한을 잃을 때도 비운다.
- 미리보기는 획을 시작할 때 잡아 둔 도구 설정으로 그린다. 서버에 보내는 값과 같아야 하며, 획 도중 도구를 바꿔도 이미 그린 획의 모양이 변하지 않는다.
- 지우개는 미리보기 레이어가 투명해 `destination-out`이 지울 대상이 없다. 지우개 획은 예전과 똑같이 본 캔버스에서만 반영된다.
- 영향: `DrawingCanvas.tsx`의 `redraw`·`finish`·`settlingRef`

### D-32 제시어 종류 — 단어와 속담

- 대표님 결정: 단어뿐 아니라 속담도 제시어로 낼 수 있게 별도 옵션을 둔다. **일반 모드와 진행자 모드 둘 다** 쓴다.
- 적용안: 대기실 설정에 「제시어 종류」를 추가한다. `단어`(기본 낱말 763개)와 `속담`(150개) 중 하나를 고르고, 기본값은 단어다. 제한 시간·정답 판정 모드와 같은 자리에 둔다.
- 권한은 호스트 또는 진행자다. 다른 대기실 설정과 같이 준비 단계에서만 바꿀 수 있다.
- **속담은 앞뒤를 모두 이어 붙인 전문이 정답이다.** 앞부분을 힌트로 주지 않는다. 정규화가 공백·구두점을 지우므로 띄어쓰기가 달라도 맞는 것으로 본다.
- 난이도를 함께 고른다. `전체`(150) / `하`(36) / `중`(78) / `상`(36). 원본은 `docs/old_sayings.csv`(앞부분·뒷부분·의미·난이도 4열), 서버 데이터는 `server/data/proverbs.json`이다.
- 종류나 난이도가 **실제로 바뀌면** 추천 제시어를 새 풀에서 다시 뽑고 열람 기록을 비운다. 이전 풀의 제시어가 남아 있으면 안 된다. 같은 값을 다시 보내면 아무것도 바꾸지 않는다.
- **다시 뽑기 횟수는 깎지 않는다.** 담당자가 고른 것이 아니라 방 설정 변경이다.
- 제시어가 잠겨 있으면 종류를 바꿀 수 없다(`KEYWORD_LOCKED`). 풀을 바꿔도 어차피 잠긴 제시어로 시작하므로 혼선만 준다.
- 난이도 선택은 속담에만 붙는다. 단어 목록에도 `difficulty` 1~3이 있으나 지금은 쓰지 않는다. 필요해지면 같은 설정을 확장한다.
- 계획 단계에서 속담을 「그림으로 내기 어렵다」며 기본 목록에서 뺐던 판단(`keyword-shuffle.test.ts`)은 그대로다. 속담은 **별도 옵션으로만** 나온다.
- 영향: `SET_KEYWORD_SOURCE`, `keywordSource`·`proverbDifficulty`, `server/data/proverbs.json`, `keywordPool`, 「제시어 종류」 패널

### D-34 속담 난이도 중복 선택

- 대표님 결정: 난이도를 하나만이 아니라 여러 개 고를 수 있게 한다.
- 적용안: `proverbDifficulty: 'ALL'|'EASY'|'NORMAL'|'HARD'` → `proverbLevels: ('EASY'|'NORMAL'|'HARD')[]`. 「전체」는 따로 두지 않고 셋 다 고른 상태다(기본값).
- 하나도 고르지 않은 상태는 막는다 — 화면에서는 마지막 하나를 끌 수 없고, 서버는 `INVALID_PAYLOAD`로 거절한다. 서버는 하·중·상 순으로 정리해 저장하므로 순서만 다른 같은 설정은 「바뀌지 않음」으로 본다.
- 화면: 하·중·상을 켜고 끄는 작은 버튼. 큰 화면은 「단어 속담」 아래 줄에, 1300px 이하는 「단어」「속담」 오른쪽에 세로로. 다른 사람에게는 「속담 · 난이도 중, 상」처럼 보인다.
- 영향: `SET_KEYWORD_SOURCE`, `PublicState.proverbLevels`, `keywordPool(source, levels)`, `PROVERB_LEVELS`

### D-35 속담 정답 — 같은 속담의 다른 표현도 인정

- 대표님 결정: 속담은 여러 가지로 말할 수 있는데 한 가지만 정답이라 아쉽다. 다양한 표현을 후보로 두고 하나만 맞혀도 정답. 정답 공개는 대표 하나.
- 인정 범위(대표님 선택 ①): **같은 속담을 다르게 말한 것만.** 낱말 바꿈(적↔시절, 나무란다↔나무라다), 조사·어미 차이(못 한다↔못한다, 장날이다↔장날), 널리 쓰는 변형(미운 아이 떡 하나 더 준다), 앞뒤 순서를 바꾼 것.
  - 인정하지 않음: 반쪽만 맞힌 답(「김칫국부터 마신다」, 「배보다 배꼽」), 뜻만 비슷한 다른 속담(「금강산도 식후경」, 「다 된 밥에 재 뿌리기」), 한자 성어(「궁즉통」).
  - 조사·어미를 자동으로 무시하는 방식(③)은 엉뚱한 답이 정답이 될 수 있어 쓰지 않았다. 표현은 하나하나 적는다.
- 적용안: `server/data/proverbs.json` 각 속담에 `aliases`. 라운드를 시작할 때 `acceptedAnswersFor(제시어)`로 인정 표현들(정규화)을 `round.acceptedAnswers`에 담고, 추측은 그중 하나와 같으면 정답이다. 담당자가 직접 고친 제시어는 그 글자만.
- 검증: 서로 다른 속담의 표현이 겹치지 않는지, 대표 문장이 늘 들어 있는지 테스트로 지킨다.
- 표현을 더 넣으려면 `aliases`에 적기만 하면 된다.

### D-36 속담 159개 추가 — 표준국어대사전 등재 속담만

- 대표님 결정: 속담을 늘리되 **하·중 난이도만**, 그리고 **공인된 속담만** 넣는다.
- 출처: 국립국어원 우리말샘의 「전문가 감수 정보」(표준국어대사전 등재 속담). 후보마다 사전을 조회해 **속담 표제어와 글자까지 일치**하는 것만 넣었다. 글자는 사전 표제어를 따른다(예: 「핑계 없는 무덤이 없다」).
  - 조회: `opendict.korean.go.kr/search/searchResult?dicType=2&spCode=5&infoType=confirm` (속담·관용구 중 속담, 전문가 감수)
  - 후보 243개 → 사전 일치 181 + 표기만 다른 10(사전 표기로 고침) → 생소한 것·기존 속담과 사실상 같은 것(「기는 놈 위에 나는 놈이 있다」 ↔ 126번)·뜻이 거꾸로인 짝(「겨 묻은 개가 똥 묻은 개를…」) 제외 → **159개(하 78, 중 81)**.
  - 사전에 속담 표제어로 없는 것은 넣지 않았다(「팔은 안으로 굽는다」, 「꿩 대신 닭」, 「장님 코끼리 만지기」 등).
- 정답 후보(D-35 ①안): 사전 표제어의 이형(「가는[가던] 날이 장날」의 [ ]·( ))과 **표현이 거의 같은 동의 속담**만(달걀↔계란, 장님↔봉사). 사전의 「동의 속담」은 뜻이 같은 다른 속담인 경우가 많아(「가재는 게 편」↔「검둥개는 돼지 편」) 그대로 넣지 않았다.
- 대표님 검토: 새 「중」 가운데 평소 잘 안 쓰는 37개를 「상」으로 올렸고(「물 위의 기름」, 「배부른 흥정」 등), 「중」 전체를 다시 보고 5개를 더 올렸다(125·134·233·240·285).
- 정답 후보 보강: 새 속담에 평소 말하는 표현 405개를 더했다(「핑계 없는 무덤 없다」, 「소귀에 경 읽기」, 「죽 쒀서 개 준다」). 한자 성어·다른 속담은 넣지 않는다.
- 결과: 309개(하 113 / 중 117 / 상 79) → D-37에서 하·중을 다시 나눔, 정답 후보는 이후 10개씩 보강해 309개 속담 전부에 2,361개(2026-10-03). 기존 속담·단어 목록과 겹치지 않음을 확인했다.

### D-37 속담 난이도 기준 — 그리기 쉬운가

- 대표님 결정: 하·중을 「잘 알려졌나」가 아니라 **「그림으로 나타내기 쉬운가」**로 나눈다. 상(평소 잘 안 쓰는 속담)은 그대로.
- 하: 장면이 눈에 보이는 사물·동물·동작으로 거의 다 그려지고, 그림만 보고 핵심 낱말이 떠오른다(고래 싸움에 새우 등 터진다, 밑 빠진 독에 물 붓기).
- 중: 추상어·말·시간·관계가 핵심이라 그림으로 전하기 어렵다(시작이 반이다, 세월이 약, 말이 씨가 된다).
- 결과: 하 127 / 중 103 / 상 79. 데이터와 원본 CSV는 난이도 → 가나다 순으로 정렬하고 번호를 다시 매겼다(번호는 프로그램에서 쓰지 않는다).


### D-38 팜 리젝션 — 펜이 만든 터치는 막지 않는다

- 증상(대표님, 크롬북 + 크롬북 펜): 팜 리젝션을 넣은 뒤 메뉴를 펜으로 누르면 아예 반응하지 않았다.
- 원인: 크롬북은 펜 접촉도 터치 이벤트로 보내는데, 아이패드처럼 `touchType: 'stylus'` 표시가 없다. 펜이 닿는 순간 「펜 사용 중」이 되고, 바로 그 펜 터치를 손바닥으로 보고 막아 클릭이 사라졌다.
- 결정: 펜 포인터가 닿은 위치(down·move·up)를 기억하고, 그 위치에서 8px 안의 터치는 펜으로 보고 통과시킨다. 펜 끝에서 떨어진 손바닥 터치는 그대로 막는다. 아이패드의 stylus 판별은 유지.
