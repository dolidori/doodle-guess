# Doodle Guess 기술 스택 정의서

## 1. 결정 요약

Doodle Guess는 브라우저 React 클라이언트와 단일 Node.js 권위 서버로 구성한다. Room과 게임 상태는 서버 메모리에만 두고 서버 재시작 시 복구하지 않는다.

근거:

- 서버 권위: 공통 지침 §1.2
- 멀티룸·벡터 캔버스: `게임 설명.md` 1~2행, 6행
- 탭별 재접속: 공통 지침 §2.3, `결정_기록.md` D-15~D-16
- 30명 포함 정원: D-03
- 호스트 비이양·30분 종료: `게임 설명.md` 14행, D-17
- 일회성 인메모리 세션: D-18
- 서버 권위 라운드 제한 시간: D-21
- 아래 라이브러리와 배포 형태는 게임 설명에 없어 결정한 구현 규칙이다.

## 2. 런타임과 언어

| 영역 | 기술 | 사용 이유 |
|---|---|---|
| 공통 언어 | TypeScript strict mode | 이벤트·상태 계약을 클라이언트와 서버에서 공유 |
| 서버 런타임 | Node.js LTS | 단일 이벤트 루프 Room 큐와 WebSocket 팬아웃 |
| 클라이언트 | React + TypeScript | 역할별 화면과 reducer 기반 서버 상태 반영 |
| 빌드 | Vite | 클라이언트 개발 서버, 정적 번들, PWA 연동 |
| 패키지 관리 | npm | 단일 lockfile로 재현 가능한 설치 |

의존성의 정확한 버전은 첫 구현 커밋의 `package-lock.json`으로 고정한다. 운영·CI는 lockfile을 변경하지 않는 `npm ci`를 사용한다.

## 3. 네트워크

| 목적 | 기술 |
|---|---|
| 실시간 통신 | 네이티브 WebSocket + 서버 `ws` |
| 이벤트 형식 | UTF-8 JSON, `UPPER_CASE`, protocol `v:1` |
| HTTP | Node HTTP 서버 |
| 서버 시간 동기화 | same-origin `GET /api/time`, `Cache-Control: no-store` |
| 정적 서비스 | Vite production bundle을 같은 origin에서 제공 |
| 입력 검증 | Zod strict schema |
| ID·토큰 | Node `crypto.randomUUID`, `crypto.randomBytes`, SHA-256 |

Socket.IO, Redis pub/sub, Protobuf, DB는 사용하지 않는다. 브라우저와 서버 사이의 작은 stroke batch는 압축 협상 비용을 피하기 위해 WebSocket per-message deflate를 끈다. 큰 그림 복원은 64KiB 이하 벡터 snapshot 청크로 보낸다.

WebSocket upgrade는 배포 origin allowlist를 검사한다. 한 연결은 한 Room에만 속한다. heartbeat는 45초 ping, 90초 timeout이다.

## 4. 클라이언트 상태와 캔버스

- 서버 상태: `useReducer` + Context. `PUBLIC_STATE`, `PRIVATE_STATE`, drawing delta를 reducer action으로 변환한다.
- 모달: FIFO modal queue. `ROUND_SOLVED`의 안정된 `roundId/eventId`로 중복 표시를 막는다.
- 캔버스: Canvas 2D API, Pointer Events, 정규화 좌표.
- 임시 입력: 별도 preview canvas layer. 서버 echo 전에는 권위 상태에 합치지 않는다.
- 재접속 토큰: 탭별 `sessionStorage`. 여러 탭이 서로 다른 플레이어로 동작한다.
- 음소거와 제시어 가림: `localStorage` 음소거, 컴포넌트 로컬 state 제시어 가림.
- 공개 추측 feed: 서버 `GUESS_SHARED`만 반영하며 로컬 선추가를 하지 않는다.
- 라운드 시계: `/api/time` 왕복 측정의 최소 RTT 샘플로 서버 시각 anchor를 만들고 `performance.now()` 경과량과 `roundEndsAt`으로 표시한다. `PUBLIC_STATE.serverNow`는 동기화 전 임시값·진단용이다. 브라우저 타이머는 표시 전용이며 서버 deadline을 판정하지 않는다.

## 5. PWA와 UI 기반

- `vite-plugin-pwa`로 manifest와 service worker를 생성한다.
- 이름은 `Doodle Guess`, 한글 보조 표기는 `두들 게스`다(D-01).
- `images/icon/icon-192.png`, `images/icon/icon-512.png`을 앱 아이콘 원본으로 사용한다.
- standalone display, Safe Area, 고정 헤더, viewport 잠금, `touch-action:none`을 적용한다.
- 테마는 D-19의 보라·인디고 배경, 노랑 강조, 흰 캔버스 방향을 따른다.
- 고정 드로잉 팔레트와 텍스트 라벨은 `실시간_캔버스_설계.md`의 enum을 공유한다.

## 6. 서버 모듈

| 모듈 | 책임 |
|---|---|
| `connection` | upgrade, origin, heartbeat, connection context |
| `protocol` | JSON parse, strict Zod validation, requestId, 오류 |
| `rate-limit` | 이벤트별 token bucket |
| `room-registry` | 100~999 방번호, Room Map, 생성·삭제 |
| `room-command-queue` | 방별 FIFO 직렬화 |
| `room-service` | 30명 정원, 입장·복구·퇴장·강퇴·TTL |
| `game-state-machine` | Room/ Round status 대응과 허용 전이 |
| `game-service` | phase, drawer, keyword, guess, 정답 |
| `round-timer` | roundId guard를 가진 서버 deadline 예약·취소·만료 큐 명령 |
| `server-time` | no-store 시간 동기화 응답의 수신·송신 Unix ms |
| `drawing-service` | batch, seq/revision/epoch, undo, clear, snapshot |
| `state-view` | PUBLIC/PRIVATE 수신자별 projection |
| `broadcast` | 방 내부 팬아웃과 연결별 backpressure |

Room 상태는 모듈 외부에서 직접 변경하지 않는다. 각 handler는 큐에 command를 넣고 서비스 함수가 검증과 mutation을 함께 수행한다.

## 7. 보안·개인정보

- keyword 원문과 정규화 값은 서버 메모리의 private 필드다.
- 현재 drawer와 moderator만 수신자별 `PRIVATE_STATE`에서 원문을 받는다.
- session token은 256-bit base64url 값이며 서버에는 SHA-256 hash만 저장한다.
- 구조화 로그는 requestId, event type, roomCode, playerId, error code만 기록한다.
- nickname, 공개 guess는 해당 방 사용자에게 공개되는 게임 데이터다. 최근 100개만 Room 수명 동안 메모리에 둔다.
- 모든 문자열은 Unicode code point 길이와 UTF-8 byte 길이를 함께 제한하며 제어 문자를 거부한다.
- CSP, same-origin, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`를 HTTP 응답에 적용한다.

## 8. 테스트 도구

| 수준 | 도구 | 대상 |
|---|---|---|
| 단위 | Vitest | 정답 정규화, schema, 권한, 상태 전이, drawing reducer |
| 통합 | Vitest + 실제 `ws` 서버 | 이벤트 계약, 방 큐, 재접속, PRIVATE 경계 |
| 브라우저 E2E | Playwright | 여러 탭, 마우스·터치, PWA 화면, modal 중복 |
| 부하 | k6 WebSocket 시나리오 | 600 기준·1,500 스트레스 연결 |
| 정적 검사 | TypeScript, ESLint | strict type, 미사용 코드, 위험 패턴 |

CI 필수 순서는 typecheck → lint → unit/integration → build → Playwright 핵심 시나리오다. 부하 시험은 배포 후보에서 별도 실행하고 인스턴스 사양과 결과를 보존한다.

## 9. 배포와 운영

- 서버 인스턴스는 하나만 실행한다. 수평 replica는 금지한다. Room이 메모리 권위이므로 replica 간 상태가 공유되지 않기 때문이다.
- 클라이언트와 WebSocket을 같은 origin으로 서비스한다.
- `GET /health/live`는 프로세스 생존, `GET /health/ready`는 event-loop lag와 Room 큐 수용 가능 여부를 반환한다.
- 종료 신호를 받으면 새 upgrade를 중단하고 연결자에게 `ROOM_CLOSED(SERVER_SHUTDOWN)`을 보낸 뒤 최대 5초 내 종료한다. D-18에 따라 Room은 복구하지 않는다.
- 운영 로그에 keyword, session token, 전체 payload를 기록하지 않는다.
- 일반 연결 단절 슬롯은 Room이 닫힐 때까지 유지하고 30분 호스트 TTL 또는 명시적 종료로 Room을 삭제할 때 모든 timer와 dedupe cache를 함께 해제한다.
- 라운드 시간은 준비 상태에서 host/moderator가 20~180초의 5초 배수로 설정하고 기본 60초다. 활성화 시 서버 timer 하나를 만들고 solve·next round·Room close에서 취소한다.

## 10. 성능 기준

`멀티룸_동시성_설계.md`의 기준을 그대로 적용한다.

- 기준 600 연결, 스트레스 1,500 연결
- stroke 관찰 p95 150ms 이하
- 정답 확정 p95 200ms 이하
- Room 큐 대기 p95 50ms 이하
- 방 간 데이터 유출·정상 연결 누락·최초 정답 중복 0
